## 1. 이 문서의 목적과 결정권

기존 홈의 차분한 인상과 실제 입력·사진 기능을 바탕으로 모든 PC·모바일 페이지를 하나의 제품으로 정리하기 위한 실행 문서다. 기존 기획을 축약해 기능을 없애거나, 미연결 AI·인증·서버 저장을 완료로 표현하지 않는다. 이번에 설계하는 결과는 **실제로 클릭할 수 있는 프론트엔드 체험**이며 실제 검색 백엔드는 다음 단계다.

| 우선순위 | 기준 | 적용 |
|---|---|---|
| 1 | 최신 사용자 직접 지시 | 기획서 완성 후 정지, 최소 텍스트, 현재 웹 스타일 상속, F1 짧은 명칭·로고 홈 복귀·헤더 직하단 모드 |
| 2 | 00의 최신 AGREED 제품 정책·FR, README의 로컬 병합 보정 | F1~F4 권한·저장·전송, 세 입력과 3채널 |
| 3 | 05의 최신 화면·상태 계약, 06의 최신 카피 | 전체 IA·후속 행동·복귀·오류 안내 |
| 4 | 01의 현재 웹 토큰, 실제 코드·이번 캡처 | 시각적 일관성과 재사용 범위 |
| 5 | 02·03·04·08의 실험·API·처리 계약 | 필요한 UI 상태와 미검증 의존성 |
| 이력 | 07 및 문서 내 이전 제작·비교안 | 과거 Figma의 5+5·오렌지·프레임 수는 이번 완료 증거로 사용하지 않음 |

## 4. 실제 UI 진단과 보존할 장점

### 4.1 이번 직접 확인한 자료

- 2026-11-17 현재 화면: `geugeo-frontend-v1/artifacts/master-home-desktop.png`(1440×900), `master-results-desktop.png`(1440폭), `master-results-mobile.png`(360폭).
- 실제 코드: `frontend/src/App.tsx`, `features/search/*`, `features/workspace/*`, `components/Modal.tsx`, `styles/tokens.css` 및 root의 현재 구현 재점검.
- 이전 `expanded-detail-desktop.png`, `expanded-register-desktop.png`는 과거 배치 참고 자료다. 현재 등록 검토 모달·물품 상태·크롭 UI 검증을 이 이미지로 대신하지 않는다.

### 4.2 유지

1. 홈의 넓고 차분한 뉴트럴 공간, 큰 한국어 제목, 여백으로 구분한 하나의 입력 영역.
2. 흑연 주요 버튼, 작은 옐로 물음표 발견점, 사진을 재색칠하지 않는 방식.
3. 헤더 바로 아래 두 검색 모드의 눌림형 선택, 별도 로그인·유틸리티 메뉴.
4. 입력과 참고 사진 기능, 모드별 독립 초안, 실제 파일 미리보기·갤러리 선택·수동 크롭.
5. 결과보다 지도를 앞세우지 않는 상세 구조와 샘플을 알리는 짧은 고지.

### 4.3 개선

| 관찰 | 사용자에게 생기는 문제 | 개선 계약 |
|---|---|---|
| 현재 결과가 이미지 5개+설명·조건 5개이며 종합 없음 | 최신 3채널 과업을 체험할 수 없음 | 종합 우선 세로 3섹션, 각 최대3·독립 더보기 |
| 결과 상단에 제목→넓은 샘플 띠→큰 질의 박스→필터가 누적 | 후보를 보기 전 빈 공간과 설명을 오래 지나감 | 제목·샘플 고지·질의/수정을 한 맥락으로 압축, 사진으로 시선 연결 |
| 모바일 결과에서 후보 전 상단 영역이 길고 2열 작은 사진이 이어짐 | 세 검색 기준과 비교할 특징을 늦게 발견 | 섹션별 최대3을 한눈에 이해할 구조, 이미지와 간결한 메타의 읽기 폭 확보 |
| 맥락 카드와 이미지 카드의 체계가 단일 boolean 분기에 묶임 | 종합의 사진 없음·단일 근거·부분 결과를 억지로 표현할 위험 | 미디어 기초만 공유, 의미별 카드·섹션을 분리 |
| 상태 샘플 버튼과 일반 제품 행동이 같은 흐름에 섞임 | 실제 처리가 끝난 것처럼 오해 | 샘플 상태 탐색은 별도 체험 인덱스, 정상 흐름은 실제 행동명 |

현재 캡처 세 장으로 모든 라우트·포커스·스크린리더·모바일 등록을 전수 검수했다고 주장하지 않는다. 팀의 추가 진단은 §17에 반영한다.

## 5. 단일 시각 방향

**방향: 사진과 필요한 정보가 앞서는 차분한 개인 검색 도구.** 현재 홈의 정체성을 전체 페이지로 확장한다. 새 테마·마케팅형 히어로·장식 일러스트를 추가하지 않는다.

제목의 단어별 색 변경·tracked capitals·의미 없는 eyebrow·네온/글로우·보라→파랑 그라데이션·카드 안 카드의 반복을 피한다. 이를 따르는 것만으로 디자인 품질을 보장했다고 주장하지 않으며 실제 비교·조작·가독성으로 판정한다.

색은 세 역할의 우선순위로 쓰고 면적 비율을 강제하지 않는다. 실사진의 색은 제품 팔레트 통제 대상이 아니다. F2 결과를 채널마다 다른 색으로 칠하지 않고 제목·배치·근거로 구분한다.

## 7. PC·모바일 레이아웃 기준

### 공통 구조

- 헤더는 로고/기능 설명·유틸리티·계정으로 구분한다. 별도 홈 메뉴는 없다. 로고가 `/`로 돌아간다.
- 두 검색 기능은 검색 화면의 헤더 직하단에서 선택 상태로 보이며 모바일 메뉴에서도 진입 가능하다. 비검색 화면의 전역 진입은 메뉴로 확보한다.
- 홈 중앙 컴포저의 기존 최대840px를 기본으로 사용한다. 결과·목록은 약1200px 이내의 기존 작업 폭, 상세·등록은 정보량에 맞춰 더 좁게 조절한다. 정확한 값은 실제 캡처로 확인하고 토큰화한다.
- PC에서는 페이지 제목·핵심 행동·질의 요약이 과도한 패널 높이를 만들지 않게 한다. 표면은 입력·선택·묶을 이유가 있는 정보에 사용한다.
- 모바일 좌우 여백16~20px, 필수 행동44×44px 이상. 360px에서도 긴 모드명·조건·첨부 제거·더보기·취소가 가려지지 않게 한다.
- 모바일에서 사진9장을 가로 캐러셀 하나로 섞지 않는다. 채널 순서·경계·더보기는 계속 식별 가능해야 한다.
- 화면 높이에 맞춘 고정 카드·본문 텍스트 잘라내기로 겹침을 숨기지 않는다. 긴 내용은 자연스럽게 문서 스크롤하고 모달은 내부 스크롤을 사용한다.

## 9. F2 세 입력 × 세 결과 채널의 필수 계약

### 9.1 사용자 경험

1. 글만/사진만/글+사진 모두 종합·사진 특징·설명·조건의 세 채널을 제공한다.
2. 첫 요약은 채널별 실제 후보 최대3개. 0~2개이면 있는 만큼만, 빈자리를 임의 후보로 채우지 않는다.
3. 종합은 이미지·맥락의 **OR 합집합** 기반이며 사진 없는 후보도 가능하다. 양쪽 근거가 모두 있는 후보만 허용하는 AND가 아니다.
4. 이미지 채널은 유효한 실제 공공 사진 기록만. 사진 없음/기본 이미지/깨진 URL을 실사진으로 다루지 않는다.
5. 설명·조건 채널은 사진 유무와 관계없는 전체 공개 기록 대상이다.
6. 각 채널은 독립 순위·필터·페이지/커서·복귀 맥락을 갖는다. 채널 간 동일 후보는 정상이며 한 채널 안에서만 중복을 제거한다.
7. 더보기는 해당 채널의 1~3위를 보존한 전체 목록에서4위 이후를 이어보는 기본안으로 만든다. 다른 채널에서 봤다는 이유로 누락시키지 않는다.
8. 동일 후보가 종합7위·설명·조건4위라면 설명·조건 더보기4위에서 계속 찾을 수 있어야 한다.
9. 중복 가능성 고지는 기본 화면에서 긴 문단으로 반복하지 않는다. 필요할 때 짧은 도움말로 제공한다.
10. 상세→뒤로가기에서 원래 채널·조건·페이지·스크롤을 복원한다. 직접 URL에 세션이 없으면 재입력 경로를 제공한다.

### 9.2 이번 프론트엔드와 다음 AI 단계 구별

이번에는 `sections={combined,image,context}`, `previewLimit=3`, 채널별 배열·상태·hasMore/페이지 정보의 UI 계약을 만들고 **명시된 샘플 배열**로 조작·오류·중복 사례를 검증한다. 실서비스 RRF·VLM·LLM·공공 API를 프론트에서 흉내 내 실제 검색으로 표현하지 않는다.

구 `selectSummary`의 limit5·채널 간 중복 제거를 유지한 채 섹션만 하나 늘리는 변경은 불충분하다. 이전 테스트76개가 통과했다는 사실은 새 계약의 통과 근거가 아니다. 새 계약에 맞지 않는 기대값은 요구사항을 기준으로 바꾸고, 기존 파일·취소·권한 회귀 검증은 보존한다.

| 부분 결과 | 일부 검색 방식을 완료하지 못했어요. 확인된 결과부터 보여드려요. |
| 상세 | 같은 물건인지는 아직 확인되지 않았어요. |
| 기관 | 방문 전 기관에 보관 여부를 확인해 주세요. |

| F4 | 선택한 사진이나 영역만 분실물 검색을 위해 서버에 일시 전달해요. 소중한 것들에는 자동 등록되지 않아요. |

| 현재 F4 체험 | 현재 체험에서는 서버 전송이 없어요. |

제작자용 내부 상태·인증 공급자 미정·구현 일정은 정상 제품 버튼에 넣지 않는다. 다만 **현재 체험 범위**와 샘플 여부는 실제 사용자도 알 수 있게 짧게 유지한다. 서버 미연결을 숨기면서 정식 저장 성공 문구를 쓰지 않는다.

사진 추가 창의4가이드는 기존 컴포넌트를 다듬어 유지한다. F1은 참고 사진과 모집단의 차이, 물체 크기·선명함·배경을 설명한다. F2는 분실 전 사진도 좋다는 안내, 다른 물체 최소화, 특징이 보이는 사진, 수동 영역 선택을 설명한다. 잃어버린 물건을 다시 촬영하라고 요구하지 않는다.

## 11. 권한·저장·전송 경계와 실제 구현 범위

| 영역 | 제품 필수 정책 | 이번 실제 체험/디자인 | 미연결·차기 검증 |
|---|---|---|---|
| F1 | 허용한 갤러리 전체·원본/인덱스 로컬·로그인 불필요 | 파일/폴더 선택·실제 미리보기·선택 목록·수동 크롭 | 임베딩·필수 로컬 OCR·IndexedDB 지속/성능·재방문 |
| F2 | 공개 습득물·비로그인·세 입력·3채널·개인사진 일시 처리 | 샘플 후보3채널·독립 더보기/상태·필터·복귀 | 경찰 API·서버 검색·VLM/LLM·LangGraph·랭킹 품질 |
| 지도 | 검증된 보관기관 주소·좌표에서만 상세 하단 소형 지도 | 샘플 지도에 실제 위치 아님 표시, 나머지 지도 없음 | 실제 기관 매칭·지오코딩·키·비용·외부 링크 |

F3 원본을 검색용 축소본이나 크롭으로 바꾸지 않는다. 로컬 크롭은 파생 파일이며 원본 File은 보존한다. F1 갤러리 전체가 F3 또는 F2에 자동 등록·전송되지 않는다. 모드 전환만으로 참고 사진을 복사하지 않는다.

파일명만 확보하면 `파일명 복사`, 폴더 내 상대경로를 확보하면 `폴더 내 경로 복사`로 표시한다. 절대경로·임시 object URL을 원본 위치라고 안내하지 않는다. 실제 지원하지 않는 기능은 클릭 성공을 꾸미지 않는다.

## 12. 상태·접근성·동작 계약

- 입력: empty/typing/attached/reading/invalid/submitting 구분. 글·사진 둘 다 없으면 제출 차단, 한글 IME 조합 중 Enter 제출 방지. 읽기 중 키보드/버튼 우회 제출 차단.
- 모달: 이름·설명 연결, 열릴 때 적절한 초점, 닫기/Escape·탭 이동·이전 초점 복귀, 긴 폼과 키보드에서도 확인/취소 접근.
- 사진: 실제 파일·샘플·사진 없음·표시 오류 분리, 물건 전체를 볼 수 있는 미디어 표시, object URL 교체/해제 수명 유지.
- 갤러리: 폴더 미연결·권한 거부·미지원·원본 이동·브라우저 정보 삭제·일부 준비 실패·재연결을 구분. 준비가 안 된 상태를 준비 완료로 만들지 않음.
- F2: 채널별 상태 알림·재시도, 실제 없는 건수/확률/단계 표시 금지. 검색 조건 변경은 새 질의로 처리하고 이전 응답이 덮어쓰지 않게 함.
- F3: 게이트·취소·목적지 복귀, 등록 검토, kept/lost/found 상태, 원본/벡터 부분 실패, 삭제 확인 유지. 현재 체험은 서버 처리 중을 실제처럼 보여주지 않음.
- F4: 미리보기·범위·확인·취소·오류. 취소는 원래 사진 상세로, 성공은 F2 입력으로; 전달한 한 장 이외 원본에 영향 없음.
- 접근성: 주요 타깃44px, 일반 텍스트 대비4.5:1·필요한 조작 경계3:1 목표. 색만으로 선택·오류·채널 의미를 구별하지 않음. 키보드 포커스가 시각적으로 보임.
- 문서 내 모든 페이지는 h1 하나, 섹션의 h2/h3 위계. 상태 알림은 필요한 시점에만 안내하고 스켈레톤을 중복 읽히지 않게 함.
