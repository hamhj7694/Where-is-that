## 반영한 카피와 배치

- 기준 원고는 `06_UI_최신_카피.md`다. 사용자용 문구와 제작자 지침을 분리했다. 현재 화면에 존재하지 않는 모든 예외 상태를 새로 제작했다고 주장하지 않는다.
- F1 명칭은 “내 갤러리에서 사진 찾기”, 검색 범위는 “연결한 갤러리 전체”로 통일했다. 사진·스크린샷을 함께 표현하고 참고 사진과 검색 모집단을 구별했다. 잘못된 “선택한 사진만 검색” 문구는 현재 화면에서 제거했다.
- F2 명칭은 “분실물 찾기”, 공급 정보는 “경찰청 공개 습득물 정보”로 구별했다. 자연어만·사진만·혼합의 결과 예시 모두 사진 특징5개와 설명·조건5개, 각 전체보기를 유지한다. 사진만·혼합 결과에는 AI가 추정한 특징을 공식 정보와 구별해 표시한다.
- 모드별 제목·설명·입력 레이블·CTA를 교체했다. 참고 사진 추가/제거, 사진 처리 범위, AI 오류 가능성, 공공 기록의 사진·설명 누락 한계를 안내한다.
- F3는 등록 원본 전체와 사진별 AI 검색 정보/임베딩의 계정 서버 저장·확인·삭제를 안내한다. 물건 이름/분류/색상·특징/추가 설명 필드를 배치했다. 실패를 완료로 표현하지 않는다.
- F4는 선택한 사진 또는 영역의 일시 전달·F3 자동 등록 없음·취소를 안내한다. 모바일 사진 영역을 줄여 고지와 행동을 가깝게 묶었다.
- 네비게이션은 홈과 두 검색 기능을 함께 유지한다. 현재 기능의 선택 표시도 맞췄다.
- 데스크톱 입력은 우측184×132 참고 사진과 하단 툴바로 정렬했다. 주요 검색 버튼은176×48로 고정했다. 모바일 첨부 버튼120×48과 검색 버튼 FILL, 하단16px inset을 적용했다. 첨부 제거는44×44다.
- 모바일 첨부 본문을 HUG + 최소184px로 바꾸고, 의미 단위 줄바꿈을 적용했다. 헤더의 잘못 늘어난 높이를 데스크톱88px/모바일72px로 교정했다. 중복 제목10개를 제거했다.
- F2 상세의 사진·물품 정보 뒤에 보관기관 및 위치를 배치하고, 지도는 하단350×200(작은 폭에서는 FILL)의 샘플 보조 요소로 유지했다. 검증되지 않은 실제 주소·좌표·전화·기관을 만들지 않았다.

| 번트오렌지 | #B64622 | 주요 행동·선택·브랜드 발견점 |

흰 Surface, 중립 글자/경계, Hover와 선택 Tint를 파생 역할로 사용하고 오류의 의미 색은 유지했다. 사진 색은 재색칠하지 않았다. 기존 문서의 코발트/초록 초안은 이번 사용자 색상 변경 지시로 대체한 시각 제안이며 제품 정책 변경은 아니다.

60:30:10은 면적 강제 공식으로 사용하지 않았다. 70:30:10은 합계110%이며, 사진 중심 검색 화면에 검정30%·오렌지10%를 억지로 채우지 않았다. 시각적 우세·보조·강조의 참고 기준으로 해석했다. [Utah Design System의 Color 지침](https://designsystem.utah.gov/guidelinesStandards/designGuidelines/color)

1. **three-color-product-design** — 이번 작업에서 직접 작성·설치했다. 의미별 토큰, 사진 우선 위계, 비율의 한계, 실측 대비와 Figma 검수를 담았다. `contrast.py`와 스킬 구조 검증을 실행했다.
2. **frontend-design** — [Anthropic 공식 GitHub 스킬](https://github.com/anthropics/skills/tree/main/skills/frontend-design)을 실제 다운로드했다. 설치 폴더는 `C:/Users/mbc/.codex/skills/studio-frontend-design`, 원문 이름은 frontend-design이다. Apache-2.0 LICENSE.txt를 함께 보존했다. 원문을 읽고 주제에 맞는 위계·타이포·절제·스크린샷 비평 지침을 적용했다. 별도 AI 서비스/CLI를 실행한 것이 아니다.

두 스킬은 다음 대화에서도 발견해 사용할 수 있다. Hallmark/Impeccable/Emil/Superdesign은 조사 또는 비교 대상으로만 검토했으며 설치·실행했다고 주장하지 않는다.

## 검수 증거와 한계

- 실제 파일: 41 Variables, 11 Text Styles, 7 Component Sets, 57 Component Masters를 유지·수정했다. Archive 복제본은 이 수에서 제외했다.
- 실제 로드 성공 폰트: Noto Sans KR Regular/Medium/Bold.
- 현재105개 프레임의 가로 넘침·부모 영역 초과·헤더와 본문 겹침·44px 미만 연결 조작 영역: 0건. 기존 잘못된 카피 검색 결과0건.
- 자연어/사진/혼합 정상 결과 샘플7개를 실제 노드로 검사해 각각5+5를 확인했다(1440/390 각3개, 360 기본 결과1개).
- 실제 반응 연결1028개(8개 모의 지연 포함)의 목적지노드 누락0건. **1028개를 모두 클릭한 것은 아니다.**
- 실제 프로토타입 클릭/스크롤 확인: 홈1:372 → F2선택1:476 → 후보1:980 → 상세1:1892 → 하단 보관기관/소형지도.
- 디자이너/기획/QA 에이전트가 코드·원고 및 최종 PNG를 검토했다. 최종 대표 PNG에서 눈에 띄는 잘림·겹침·버튼 충돌 없음. PNG 검수는 실제 앱 접근성 동작 검증을 대신하지 않는다.
- 대비 직접 계산: 차콜/웜화이트14.96:1, 흰 글자/주요 오렌지5.40:1, 보조 글자/웜화이트6.02:1, 입력 경계/웜화이트3.20:1. 일반 글자4.5:1·필요한 UI 경계3:1 기준을 참고했다. 화면 전체의 모든 투명도 조합·키보드/스크린리더를 전수 검사했다고 주장하지 않는다. [W3C 글자 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [비텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

1. 실제 VLM·공공 API로 세 입력×두 경로의 품질·누락·실패·비용·지연·전송 정책을 검증한다. 현재 사진·결과·등록·지도는 샘플이다.

3. 아직 별도 프레임을 만들지 않은 브라우저 미지원 단독 상태, F3 원본 저장 실패 단독 상태, 지도 address_only/ambiguous/provider_error 등 06의 나머지 원고를 실제 계약에 맞춰 확장한다. 현재 missing 무지도 대체와 샘플 지도는 존재한다.
4. 360px 전체 상태 확대와 F1/F3/F4 전체 프로토타입 클릭·실제 포커스·스크린리더·확대 검수를 진행한다. 현재360px 검수는 주요7개다. 특징 수정/제거·사진 선택·원본 열기 등은 제품 기능 구현을 뜻하지 않는다.
