**F2 입력·검색·결과 계약 [AGREED · 2026-11-16 최신]:** `자연어만 / 사진만 / 자연어+사진` 모두 **종합·이미지·맥락 3개 검색 결과 채널**을 지원한다. 검색 모집단은 F2 공개 습득물로 한정한다. `종합`은 이미지·맥락 경로 후보의 **OR 합집합**을 확보한 뒤 여러 근거로 재정렬하는 기본 탐색 채널이며, 사진 없는 기록도 포함 가능하다. `이미지`는 실제 유효 습득물 사진이 있는 기록을, `맥락`은 사진 유무와 관계없는 전체 공개 기록을 대상으로 한다. **각 채널은 독립된 정렬/페이지네이션을 유지하며, 동일 레코드의 채널 간 중복 노출을 허용한다. 같은 채널 내부의 중복 레코드는 제거한다.** 초기 UI는 **각 최대 3건 미리보기 + 해당 채널 더보기**(3+3+3)이며 실제 후보가 적으면 그만큼만 보여준다. 더보기에서 같은 채널의 4위 이후로 연속 탐색할 수 있고, 다른 채널에서 이미 봤다는 이유로 건너뛰지 않는다. 3건 수는 사용성 검증 후 변경 가능하다.

**AI·검색 경계 [AGREED: 목표 / OPEN: 구현 성능]:** 자연어만 입력해도 공개 유효 사진의 **VLM 사전 해석 맥락**과 텍스트↔이미지 임베딩으로 이미지 후보를 찾고, 사진만 입력해도 **VLM이 검색 설명·조건을 추출**해 맥락 검색을 수행한다. 자연어+사진은 두 단서를 함께 반영한다. LLM 질의 구조화·OCR·객체 탐지·크롭·임베딩은 독립 모듈이며, F2는 **LangChain+LangGraph 중심의 조건부 워크플로**를 설계 방향으로 채택한다(MCP는 MVP 불필요). 모델의 파인튜닝은 필수가 아니지만 **평가용 정답셋**은 반드시 만든다. 이미지·맥락 점수의 단순 평균이나 `동일 물건 확률` 표시 금지. RRF 등 결정적 랭킹 모듈을 비교 실험하고, 채널별 부분 오류·검색 상태는 분리한다. F1 로컬 개인정보·F3 등록 원본+사진별 벡터 계정 저장·F4 명시적 일시 전달 원칙은 변경하지 않는다.

## 0. 이 문서로 만들 것 / 만들지 않을 것

**만들 것**: 브랜드 워드마크·심벌 시안, 디자인 토큰, 재사용 컴포넌트, desktop/mobile 주요 화면, 각 기능의 정상·로딩·오류·권한·빈 결과, 핵심 사용자 흐름 프로토타입, 최종 개발 핸드오프.  
**만들지 않을 것**: API 검증 전 실제 경찰 데이터를 조회하는 것처럼 꾸민 화면; F1 사진이 서버에 자동 업로드되는 화면; F2 전체 지도를 메인 UX로 만든 화면; 로그인·백업을 F1 검색 혜택으로 내세운 화면; F2를 소유권 확정·반환 보장으로 표현한 결과.

## 1. 브랜드 ID와 이야기

### 이름 및 카피 계층

- 워드마크(우선 채택 작업안): **그거어디?**
- 헤더 옆 디스크립터(권장): **내 사진 · 내 물건 찾기**
- 사용자 요청 장문 카피 비교안: **내 사진 내 물건 그거찾기**. 헤더에서 읽기 복잡한지 실제 A/B 확인. 문장으로 쓰면 `내 사진도, 내 물건도. 그거찾기!`를 캠페인형 후보로 사용.
- 브랜드 비전(기획 문서): **소중한 순간과 물건을, 기억나는 단서만으로 다시 찾을 수 있도록.** 그러나 UI 헤드라인에서 ‘단서’를 반복적으로 강조할 필요는 없음.
- 브랜드 경험의 서사: **그거 어디 있지? → 기억나는 말이나 사진으로 찾아보기 → F1: 아, 여기 있네! / F2: 혹시 이 물건인가요?**
- 과제 공식 주제: `AI 기반 개인 사진 탐색 및 유실물 검색 웹서비스`. 브랜드명이 공식 주제를 대체하지 않음.
- 상표·도메인·기능 오인 검증 전 외부 출시명 법적 확정 아님(`EXP-23`).

### 톤앤매너: Calm & Meaningful (최신 Figma 시안 기준)

1. **인상**: 믿을 수 있고 차분하지만 건조하지 않은 개인 검색 도구. 필요한 곳에서만 따뜻한 발견의 기쁨.
2. **레퍼런스 방향**: 차분한 에디토리얼 공간, 명확한 검색 입력, 정보가 우선인 결과 카드, 따뜻한 뮤트 컬러. 과도한 AI 네온·글래스모피즘·캐릭터 남발·경찰/탐정 상징 금지.
3. **감성의 위치**: 홈 헤드라인·온보딩·F1 실제 발견 성공. **오류·보안·유실물 후보·연락 안내는 사실 중심 카피**.
4. **사진 중심**: 제품 설명이 길어도 사진·물품 썸네일 자체가 가장 눈에 띄게. 지도는 F2 상세 하단의 보조.
5. **이미지 정책**: 실제 데이터 미확보 단계의 썸네일·지도·기관은 `샘플`임을 표시. 가짜 습득물 기관명이나 관리번호를 실제처럼 묘사하지 않음.

### 현재 웹 디자인 토큰 — 2026-11-17 병합 기준 [CURRENT / 사용자 방향]

현재 React 프론트엔드의 홈 스타일을 다른 페이지에 상속한다. 실제 값은 [tokens.css](../frontend/src/styles/tokens.css)를 기준으로 한다. 07의 웜화이트·차콜·번트오렌지는 과거 Figma 시안의 관측 이력이며 현재 웹 토큰을 대체하지 않는다.

| 토큰 역할 | 현재 웹 값 | 용도 |
|---|---|---|
| `--page` | `#FAFAF8` | 기본 배경 |
| `--surface` | `#FFFFFF` | 입력·표면 |
| `--ink`, `--text-primary` | `#222322` | 본문·주요 행동 |
| `--accent` | `#E5DB72` | 작은 브랜드 발견점·제한적 강조 |
| `--text-secondary` / `--text-muted` | `#5D625B` / `#656A62` | 보조 글씨 |
| `--line` / `--control-line` | `#DEDFD9` / `#868C81` | 구분선·조작 경계 |
| `--negative` | `#A63B32` | 오류 의미색 |

- 서체: 현재 웹은 로컬 Pretendard Variable을 사용한다. Noto Sans KR은 과거 Figma 로드 확인 서체다. Figma 서체를 실제로 교체했다고 간주하지 않는다.
- 타입·간격·반경은 기존 CSS 토큰을 재사용한다. 새 페이지마다 별도 팔레트나 장식을 만들지 않는다.
- 주요 조작 영역 44×44px 이상, 보조 글씨 약13px, 일반 본문 대비 4.5:1을 목표로 실제 검수한다.
- 홈에는 예시 사진을 상시 배치하지 않는다. 참고 사진 추가 창에서 준비 가이드4개를 제공한다. 두 검색 모드는 헤더 직하단의 눌림형 선택 상태로 표현한다.
- 텍스트는 과업·행동·필수 한계와 저장/전송 범위에 집중한다. 모바일의 화면 체험 버튼은 표시하지 않는다.

### 현재 워드마크와 과거 탐색 기록

현재 웹의 워드마크·작은 옐로 발견점을 단일 기준으로 확장한다. 아래 L1~L3는 과거 탐색 참조이며 이번 작업에서 비교 시안3개를 새로 제작하라는 지시가 아니다.

| 안 | 상징 | 기대효과 | 리스크/판정 과제 |
|---|---|---|---|
| **L1 워드마크 중심** | `그거어디?` 물음표의 점을 발견점으로 변형 | 작은 공간에서 브랜드 인지 | 부호 없을 때도 동일성 확보 여부 |
| **L2 포커스 프레임** | 사진 프레임 4개 코너 + 하나의 초점 점 | 이미지·검색 모두 의미 | 일반 검색·QR 스캔과 차별화 여부 |
| **L3 돋보기+발견점** | 절제된 돋보기 안의 이미지 요소 | 기능 직관성 | 흔한 돋보기 아이콘과 중복, 확대경 오해 |

**적용 범위:** 현재 단일 워드마크를 가로·컴팩트·흑백·작은 아이콘 환경에서 확인한다. 별도 비교 홈 시안을 요구하지 않는다. 상표·사용자 검증은 여전히 미완료다.

### 3.1 F2 3중 결과·Figma 반영 기준

- 최신 제품 합의는 **종합 / 이미지 / 맥락** 세 결과 채널, **각 최대 3개 미리보기 + 해당 채널 더보기**다. 종합 후보는 이미지/맥락 원천 검색의 **OR 합집합**으로 생성(양쪽 근거가 반드시 있어야 하는 AND 아님), 이미지 채널은 **유효 공공 실사진만**, 맥락은 사진 없음 포함 전체 기록을 대상으로 한다.
- 채널 간 **같은 후보가 반복 등장해도 정상**이다. 한 채널 안에서만 중복 레코드를 제거한다. **종합 7위·맥락 4위인 물건은 맥락 더보기 4위에 계속 나타나야 한다.** 다른 채널의 노출을 이유로 숨기거나 순위를 압축하지 않는다.
- 기존 `F2-05`의 5+5 프레임은 **과거 Figma 구현 기록**이다. 실제 Figma [Product Design v1.0](https://www.figma.com/design/4vyCK5PE10UXRl1jXuNiDn)에 이번 3중 구조를 아직 적용하지 않았으며, 이 문서를 업데이트했다고 105개 화면을 재검수·수정했다고 주장하지 않는다.
- 추가 프레임: `F2-05` 데스크톱/모바일 3+3+3, `F2-05-A` 종합 더보기, `F2-05-I` 이미지 더보기, `F2-05-C` 맥락 더보기, 각 채널 0/부분 실패·사진 없음/유효 사진 상태.
- 컴포넌트: `TripleResultSection`(combined/image/context), `FoundCombinedResultCard`, `FoundImageResultCard`, `FoundContextResultCard`, `ResultSectionMoreLink`, `NoPhotoThumbnail`, `ResultSectionStatus`.
- 결과 카드는 공식 기록과 VLM 추정을 구분하고, 사진 없는 기록에 가짜 사진·동일물건 일치 확률을 쓰지 않는다. 지도는 F2 개별 상세 하단에만 남긴다.

### 3.2 세 입력 방식의 결과 채널 생성 계약

| 입력 | 이미지 원천 | 맥락 원천 | 종합 |
|---|---|---|---|
| 텍스트만 | 텍스트↔공공 실사진의 VLM 사전 설명·멀티모달 임베딩 | LLM 명시 조건+실제 공개 제목·설명·메타 | OR 융합/재랭킹 |
| 사진만 | 입력 사진↔공공 실사진 유사도 | VLM 이미지 특징→설명·조건 검색 | OR 융합/재랭킹 |
| 텍스트+사진 | 사진 유사도+자연어 이미지 관련성 | 명시 입력+VLM 시각 특징 | OR 융합/재랭킹 |

- 이미지/맥락 검색 원천 가운데 일부가 실패하면 종합은 사용 가능한 원천만 반영할 수 있으나 `일부 검색 결과`임을 알린다.
- 각 채널 0~2개면 있는 만큼만 표시; 더보기의 4위 이후 건너뛰기 금지. 3개 표시 수와 세로/탭 선택은 실사용자 시험으로 결정한다.
- 필수 VLM 이해 목표와 외부 전송 동의·로그/보존 제약을 지킨다. `F1`은 브라우저 로컬 OCR 포함, 서버 LangGraph 필수 경로로 연결하지 않는다.
- 세부 화면·컴포넌트/상태/와이어프레임은 05 §6~7, 사용자 문구는 06 §3, 테스트는 02 `EXP-24~28`을 따른다.

## 4. F2 상세 페이지: 지도의 정확한 위계

```text
[이전 결과로]                  [공식 출처 확인]
[물품 사진/확대]
[물품명]  [유사 후보/확정 아님]
습득일 · 물품분류 · 색상 · 관리번호(있는 경우)
습득 장소 (있을 때) / 접수처 (있을 때)
물품 상세 설명 및 특이사항
──────────────────────────────────────────
보관기관 및 위치    ← 상세 페이지의 **하단 보조 섹션**
기관명 / 확인된 주소 / 연락처 / 정보 확인일
[소형 단일 마커 지도: verified일 때만]
[지도에서 보기] [길찾기] [공식 상세 확인] [전화]
※ 실시간 위치가 아니며 방문 전 보관 여부를 문의하세요.
```

**디자인 상태 6개**

1. `verified`: 보관기관 주소+좌표 검증 → 소형 지도 + 전화/외부 길찾기.
2. `address_only`: 공식 주소는 있으나 지오코딩 미확정 → **지도 없음**; 주소와 공식 문의 표시.
3. `ambiguous`: 같은 이름 기관 여러 곳 → **지도 없음**; 첫 검색 결과 임의 선택 금지.
4. `missing`: API에 기관/주소 누락 → **지도 없음**; 공식 상세 링크.
5. `provider_error`: 지도 API 장애·쿼터 초과 → **지도 없음**; 기관명/전화/주소 유지.
6. `record_changed`: 물품 반환/기록 변경 의심 → 갱신/출처 확인 안내, 지도가 남더라도 물건 보관 확정 금지.

**범위 밖:** 지도 중심 홈, 주변 습득물 탐색, 결과 목록 핀 지도, 지도 기반 정렬, 서비스 내부 경로 탐색, GPS 위치 수집. 지도 SDK는 데이터 정확성 `EXP-22` 통과 시 도입, 안 되면 공식기관 안내만 남기는 것이 더 안전.

| 이미지 섹션 | `사진 특징이 비슷한 후보` / `사진 특징 후보 더보기` | VLM 공공 사진 맥락 비교 |
| 맥락 섹션 | `설명·조건이 비슷한 후보` / `설명·조건 후보 더보기` | 사진만 입력해도 VLM 자동 설명 검색 |
| 추출 특징 | `사진에서 추정한 특징` | 공식 원문과 구별·수정 가능 |
| 공통 안내 | `AI 검색은 잘못 찾거나 놓칠 수 있어요.` | 오류·누락 가능성 |
| 공공 사진 누락 | `공개 기록에 사진이 없으면 사진 특징으로 비교할 수 없어요. 설명·조건으로도 함께 찾아요.` | 사용자 사진 미첨부와 구별 |
| F3 저장 | `등록한 사진 원본 전체와 사진별 AI 검색용 정보가 내 계정 서버에 저장돼요. 소중한 것들에서 확인하고 삭제할 수 있어요.` | 원본/벡터·삭제 경로 |
| F4 전송 | `선택한 사진이나 영역만 분실물 검색을 위해 서버에 일시 전달해요. 소중한 것들에는 자동 등록되지 않아요.` | 선택 범위·일시 처리 |

사진만 입력했을 때 “설명을 입력해야 검색 가능”을 정상 카피로 쓰지 않는다. 해석 실패·검색 실패와 추가 설명의 선택적 보완은 06의 오류 문구로 구분한다.

## 8. 사용성 검증·승인 체크리스트

- [ ] 브랜드명만 보고 GPS·위치 추적/일반 인터넷 검색을 오인하는지 기록(`EXP-23`).
- [ ] 시각적 헤더가 `그거어디?`/기능 설명/로그인/네비를 구분하고 360px에서 깨지지 않음.
- [ ] 게스트가 ① F1 ② F2 검색을 회원가입 없이 시작할 수 있음.
- [ ] F1 최초 인덱싱 비용·로컬 저장·브라우저 권한/삭제 리스크를 정확히 표현함.
- [ ] **F2 결과는 종합/이미지/맥락 각 최대 3개·채널별 독립 더보기**로 보여준다.
- [ ] **맥락 결과는 사진 없는 기록도 검색 가능**하고 이미지 섹션만 실패해도 유지된다.
- [ ] `등록된 사진 없음`은 가짜 실사로 대체하지 않는다. 이미지/맥락 검색 점수를 확률처럼 병합하지 않는다.
- [ ] F2 결과 카드와 상세를 분리; 상세 상단은 사진과 물품 정보, 지도는 **하단 보조**.
- [ ] 유사 후보와 동일 물품 확정의 차이를 누구나 이해하고, 공식 출처를 찾을 수 있음.
- [ ] 지도 데이터가 애매하거나 API가 실패할 때 **임의 핀 없음**. 기관 연락/공식 정보 경로 남음.
- [ ] F3 계정에는 **선택 등록한 모든 원본 사진+사진별 검색 벡터** 저장 사실, 삭제 경로가 적혀 있음.
- [ ] F1→F2는 사진 선택·명시적 전송 클릭 후 일시 처리, 자동 F3 등록 없음.
- [ ] 모바일 터치·스크린리더·키보드·색 대비·긴 텍스트·이미지 없음/중복 등 상태 검수.
- [ ] 컴포넌트와 페이지의 미검증 상태는 `DEMO` / `PROPOSED` / `AGREED` 중 하나로 표시.

- [ ] 자연어만 / 사진만 / 자연어+사진 각각에서 이미지·맥락 두 검색 원천으로 **종합/이미지/맥락 세 채널**을 구성한다.
- [ ] 자연어만으로 공공 사진의 VLM 맥락을 비교하고, 사진만으로 입력 사진의 VLM 설명·조건을 추출한다.
- [ ] 각 결과 채널 0/1/2/3/4건 이상에서 최대 3건 미리보기와 **4위 이후 독립 더보기**를 확인한다.
- [ ] 더보기는 채널별 독립 정렬·검색 상태/필터·복귀 맥락을 유지한다. 채널 간 동일 레코드 **중복 노출 허용**, 동일 채널 내부 중복/다른 채널 노출로 인한 후보 누락 **0건**을 확인한다.
- [ ] 사용자 사진 미첨부와 공공 기록 사진 누락을 구분하고, 사진 없는 공개 기록을 맥락 검색에 남긴다.
- [ ] VLM 실패·시간 초과·해석 불확실·동의 필요·0건을 구분한다. 정상 경로는 유지하고 실패 경로만 재시도한다.
- [ ] 공공 원문과 VLM 파생 특징의 출처를 구분하고, 모델/프롬프트 버전·처리 시각·이미지 버전·상태를 추적한다.
- [ ] F1 전체 갤러리 무단 전송·F3 자동 등록·경찰 API 개인 사진 제출이 없고, 필요한 외부 전송 고지·동의를 확인한다.

## 9. 개발 핸드오프 파일/링크 규칙

- Figma frame별: `frame_id`, `route`, `user_goal`, `FR-ID`, `state`, `layout`, `data_contract`, `edge_case`, `decision_status` 기록. **전체 페이지·와이어프레임·상태 진실 원천은 `05_페이지구성_와이어프레임_UIUX_통합설계.md`.**
