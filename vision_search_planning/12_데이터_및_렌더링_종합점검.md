# 12. 데이터·서버·렌더링 종합 점검

- 작성일: 2026-11-20
- 기준: `backend` / `frontend` 실제 소스, 실행 중인 `127.0.0.1:8000`·`127.0.0.1:5173`, SQLite `backend/data/app.db`
- 이 문서는 관찰 결과를 기록한다. 기존 4개 영역의 픽스(DML)를 변경하지 않는다. 최신 화면 변경은 DML-086~089가 반영됐다.
- 최신 기준(2026-11-20 재점검): DML-113~116이 반영됐다. 특히 DML-116으로 AI 동의 팝업이 모두 제거되었고, `gpt-6-luna`의 `temperature=0.1` 미지원으로 나던 502가 제거됐다. 아래 본문 중 '동의 후'·'최신 변경 DML-086~089' 문구는 이 줄이 대체한다.

## 6. 원본 API → 정규화 → Candidate → 화면 매핑

검색 원본은 11개 태그, 상세 원본은 16개 태그다. 상세의 `address`는 경찰 원본이 아니라 Kakao `place` 폴백으로 채워진다.

| 원본(상세) | 정규화 `FoundItem` | `Candidate` | 화면 표시 |
|---|---|---|---|
| `fdPrdtNm` | `name` | `title` | 페이지 제목 |
| `fdSbjt` / `uniq` | `subject`, `notes` | `description` | `field__help` (`subject` 우선, 없으면 `notes`) |
| `prdtClNm` | `category` | `category` | `물품 분류` |
| 색상 필드 | `color` | `color` | `색상` |
| `fdYmd` + `fdHor` | `foundDate`, `foundTime` | `foundAt`, `foundTime` | `습득일시` 한 줄 `YYYY-MM-DD (요일) HH시` (DML-093) |
| `csteSteNm` | `status` | `custodyStatus` | `보관상태` (DML-086) |
| `fndKeepOrgnSeNm` | `keepType` | 미전달 | 화면 제외 (DML-087) |
| `orgId` | `orgId` | 미전달 | 화면 제외 (DML-087) |
| `orgNm` | `orgName` | `custodyName` | 보관기관명 |
| `tel` | `tel` | `tel` | `연락처` |
| `atcId` | `atcId` | `atcId` | `관리번호` (DML-086~087) |
| `fdSn` | `fdSn` | `fdSn` | URL 라우팅만, 화면 미표시 (DML-087) |
| Kakao `place.address` | `address` | `location` | 지도 패널 주소 |

`title`/`subject`가 겹치는 것은 중복 등록이 아니라 원본이 `fdPrdtNm` + `fdSbjt`를 각각 제공하기 때문이다(표본 80건 중 78건 `subject.startsWith(name)`, 완전 동일 0건, `atcId` 80건 고유).

## 9. 갤러리 AI 분석 반영 재점검 [DML-20261120-117~119]

- 위 3장의 '프론트 AI 클라이언트는 `prepareAiSearch()`만 존재, `/api/ai/vision/compare` 호출 코드 없음'은 이 절로 대체된다. `ai-search-api.ts:compareCandidates()`가 `/api/ai/vision/compare`를 호출하고 3축 점수와 참고 사진 분석 설명을 반환한다.

## 10. F2 공개 JSON 전체 매칭 데이터 흐름 [DML-20261120-120]

- 위 9장의 'F2 종합 검색어 한 문자열만 사용, 채널 키워드 버려짐'은 이 절로 대체된다. AI 계획에 `criteria`가 추가되고, F2는 `apiKeywords`로 넓게 가져온 공개 항목을 전체 JSON 텍스트로 다시 좁힌다.
- 전송 데이터: `POST /api/lostfound/search` 본문에 `{ keyword, page, rows, hints }`. `hints = { apiKeywords, include, any, exclude, imageFeatures }`. 서버 키·토큰은 포함되지 않는다. `keyword`는 대표 탐색어이며, 실제 조회는 `hints.apiKeywords`를 `PRDT_NM`에 OR로 사용한다.
- 백엔드 매칭 필드: `name`, `subject`, `notes`, `category`, `color`, `foundPlace`, `storagePlace`, `orgName`, `address`, `status`, `keepType`를 공백으로 합쳐 소문자화한다. `exclude`는 문자열 포함 여부로 제외 사유를 만들고, `include`/`any`/`imageFeatures`는 가중치(AND 3, OR/사진 1)로 `matchScore`를 만든다. 조건이 없으면 정렬 점수 0으로 원래 API 순서를 유지한다.
- 응답 추가 필드: `apiKeywords`(사용된 탐색어), `matched`(조건 근거가 있는 건수), 각 `items[].aiMatch = { hits, allInclude }`. 프론트는 이 값을 조건 카드의 'N건이 조건과 일치' 문구와 후보 근거로 사용한다.
- 렌더링: `applyCriteria()`가 NOT 제외 후보를 버리고 `matchScore` 내림차순으로 정렬한 뒤 `sortByRank()`의 AI 문맥 점수와 병합한다. AI 문맥 순위가 준비되기 전에는 JSON 조건 점수를 폴백으로 사용한다. 조건과 일치하는 후보가 없어도 넓은 공개 결과는 유지한다.
- 실측: 자연어 '신림역 근처 … 검은 가죽 지갑 … 파손된 건 아니에요'에서 `apiKeywords=지갑`, `AND=[가죽,지갑]`, `OR=[검은색,검정,블랙]`, `NOT=[파손]` 생성 후 공개 후보 표시. 지갑 참고 사진 검색에서는 `imageFeatures=[직사각형,접이식,가죽,스티치,지폐,작은 양각 글자]`가 조건과 매칭에 반영됐다.
- 데이터 경계 유지: 사진 원본·전화번호는 AI 전송 대상이 아니고, AI 요청은 서버에 저장하지 않는다. 직접 찾기의 필터·건수 정책은 11장에서 별도로 갱신했다.
- 검증: 프론트 421개, 백엔드 53개 테스트 통과. 백엔드 재기동 후 `apiKeywords/matched/aiMatch` 실호출 확인. 키·토큰 값은 기록하지 않는다.

## 11. 직접 찾기 전체 스캔·필터 기준 페이지네이션 [DML-20261120-121]

- 전송 데이터: `POST /api/lostfound/browse` 본문 `{ keyword, page, rows, maxPages, hints, filters }`. `filters`는 URL의 분류·색상·지역·시작일·종료일이고, AI `hints`는 F2와 동일한 5그룹이다. 서버 키·토큰은 포함되지 않는다.
- 조회 범위: `hints.apiKeywords`(없으면 원문 keyword)를 `PRDT_NM`에 OR로 넣어 두 소스 × 최대 20페이지를 병렬 스캔한다. 기본 스캔 rows는 40이라 전체 1,600건을 훑고, 응답의 `scanned`와 `scanLimitReached`로 범위를 알린다.
- 서버 필터: `metadata_pass()`가 분류(대분류는 하위 포함), 색상(정확 일치), 지역(습득/보관/기관/주소 텍스트 포함), 습득일 범위를 스캔한 전체 풀에 적용한다. `criteria_pass()`는 AI AND/OR/NOT·사진 특징을 하드 필터로 적용한다. `score_criteria()`의 점수는 순위에 쓰지 않고 `aiMatch.hits` 근거로만 반환한다.
- 중복 제거: 서버 `_browse_dedupe_key()`가 프론트 `dedupeLostFound()`와 같은 키로 같은 물건을 한 건으로 센다. 이로써 이전에 total 475건·화면 39건이던 불일치가 total 432건·화면 40건처럼 일치한다.
- 페이지 계산: `total = 필터·중복 제거 통과 건수`, `pages = ceil(total / rows)`, `items = 필터 결과[page 슬라이스]`. 이전처럼 API의 원본 `totalCount`(2,439,032건)를 쓰지 않는다.
- 응답 필드: 기존 `query/sources/total/items/errors/apiKeywords/matched`에 `page/rows/scanned/scanLimitReached/criteriaApplied/filtersApplied`를 추가했다. 화면 상단 요약이 스캔 건수와 적용 필터 수를 표시한다.
- 데이터 경계: AI 요청에는 사진 원본·전화번호가 없고 서버에 저장하지 않는다. AI 실패 시 `hints`를 비우고 원문 검색을 실행해 공개 목록이 막히지 않는다. 공개 API 순서(습득일·ID)는 유지하고 AI 점수 재정렬은 하지 않는다.
- 실측: 색상 필터 240건 스캔 → 59건 재계산, 분류 필터 432건·11페이지·화면 40건, 자연어 hints 240건 스캔 → 5건(AND=가죽·지갑, OR=검정·검은색·블랙·신림역 근처, NOT=파손). 2페이지 이동도 필터 기준으로 유지됐다.
- 검증: 프론트 422개, 백엔드 59개 테스트 통과, 키·토큰 값은 기록하지 않는다.

## 16. VLM 기반 객체 종류 판정으로 크롭 게이팅 보강 [DML-20261121-127]

- [BACKEND] LangGraph 시각 비교 그래프에 `census` 노드를 추가했다. 로컬 CLIP·YOLOE가 실제로 쓰이고 VLM 설정이 있을 때만, 참고 사진과 범위 안의 공개 사진을 한 번의 멀티모달 호출로 세어 `objectCount`/`objectTypes`를 받는다. 프롬프트는 `backend/prompts/crop_census.txt`다.
- [BACKEND] VLM이 `객체 수 >= 2` 또는 `서로 다른 종류 >= 2`라고 판정한 사진은 YOLOE가 단일 객체로 봤어도 크롭한다. 반대로 VLM이 단일 객체라고 해도 YOLOE가 여러 객체를 보면 크롭을 유지한다(OR 조건). `vlm_multi` 힌트는 `score_similarity`, `score_text_image_similarity`, `crop_notes`까지 전달한다.
- [BACKEND] `GEUGEO_VLM_CROP_CENSUS`(기본 true)로 켜고 끌 수 있다. 호출 실패·형식 오류·미설정이면 빈 힌트를 반환해 기존 YOLOE 게이팅으로 되돌아가고 검색 자체는 실패하지 않는다. 키·토큰 값은 요청·응답·로그·문서에 넣지 않는다.
- [FRONTEND] UI·카피·데이터 경계 변경 없음.
- 검증: 백엔드 pytest 91개 통과(그래프 라우팅·결과 매핑·실패 폴백·힌트 전달 포함).
