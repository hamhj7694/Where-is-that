# 그거어디? — 최신 UI 카피

> 로컬 통합본: 2026-11-17 · 첨부 개정판과 최신 사용자 UI 지시를 병합. 변경·구현 상태는 `README_최신설계_및_작업순서.md` 참조.

v1.1 · 2026-11-16 · 검토 반영 원고 · 현재 **문서 기준 최신 원고**. 3중 결과 카피는 **기존 Figma 파일에 아직 미반영**

**F2 입력·검색·결과 계약 [AGREED · 2026-11-16 최신]:** `자연어만 / 사진만 / 자연어+사진` 모두 **종합·이미지·맥락 3개 검색 결과 채널**을 지원한다. 검색 모집단은 F2 공개 습득물로 한정한다. `종합`은 이미지·맥락 경로 후보의 **OR 합집합**을 확보한 뒤 여러 근거로 재정렬하는 기본 탐색 채널이며, 사진 없는 기록도 포함 가능하다. `이미지`는 실제 유효 습득물 사진이 있는 기록을, `맥락`은 사진 유무와 관계없는 전체 공개 기록을 대상으로 한다. **각 채널은 독립된 정렬/페이지네이션을 유지하며, 동일 레코드의 채널 간 중복 노출을 허용한다. 같은 채널 내부의 중복 레코드는 제거한다.** 초기 UI는 **각 최대 3건 미리보기 + 해당 채널 더보기**(3+3+3)이며 실제 후보가 적으면 그만큼만 보여준다. 더보기에서 같은 채널의 4위 이후로 연속 탐색할 수 있고, 다른 채널에서 이미 봤다는 이유로 건너뛰지 않는다. 3건 수는 사용성 검증 후 변경 가능하다.

**AI·검색 경계 [AGREED: 목표 / OPEN: 구현 성능]:** 자연어만 입력해도 공개 유효 사진의 **VLM 사전 해석 맥락**과 텍스트↔이미지 임베딩으로 이미지 후보를 찾고, 사진만 입력해도 **VLM이 검색 설명·조건을 추출**해 맥락 검색을 수행한다. 자연어+사진은 두 단서를 함께 반영한다. LLM 질의 구조화·OCR·객체 탐지·크롭·임베딩은 독립 모듈이며, F2는 **LangChain+LangGraph 중심의 조건부 워크플로**를 설계 방향으로 채택한다(MCP는 MVP 불필요). 모델의 파인튜닝은 필수가 아니지만 **평가용 정답셋**은 반드시 만든다. 이미지·맥락 점수의 단순 평균이나 `동일 물건 확률` 표시 금지. RRF 등 결정적 랭킹 모듈을 비교 실험하고, 채널별 부분 오류·검색 상태는 분리한다. F1 로컬 개인정보·F3 등록 원본+사진별 벡터 계정 저장·F4 명시적 일시 전달 원칙은 변경하지 않는다.

카피의 목적·범위는 00, 화면 계약은 05, 시각 실행은 01을 따른다. 아래 문구는 화면에 적용할 원고이며 실제 기능·API·VLM 검증 완료를 주장하지 않는다. 제작자 지침은 사용자에게 노출하지 않는다.

## 문구를 판단하는 기준

서비스는 사용자가 기억하는 말이나 참고 사진으로 원하는 이미지를 찾고, 공개 습득물에서 비슷한 후보를 살펴보도록 돕는다. 큰 제목은 사용자 목적을 말하고, 작은 안내는 검색 범위·입력 방법·저장 사실·실패 후 행동을 설명한다. 제작 상태·API 구현 여부·인증 공급자 결정 여부를 실제 사용자용 문장에 섞지 않는다. 해당 내용은 디자인 주석으로 관리한다. 샘플 화면과 실제 검색 결과의 구분은 계속 표시한다.

**F1의 검색 대상은 연결한 갤러리 전체다. 참고 사진 한 장은 검색에 쓰는 입력이며, 검색 범위를 그 사진 한 장으로 제한하지 않는다.** 갤러리는 사용자가 연결하고 접근을 허용한 사진 모음이다. 기기의 모든 폴더를 허락 없이 읽는다는 뜻이 아니다. 읽을 수 없는 형식·권한 문제는 별도 상태로 알린다.

‘갤러리 전체 검색’과 ‘원본·인덱스 보관 위치’는 다른 정보이므로 한 문장으로 묶지 않는다.

## 현재 UI의 노출 원칙 (2026-11-17 병합)

- 별도 홈 메뉴 없이 로고로 돌아간다. 두 검색 모드는 헤더 직하단에서 눌린 상태로 구분한다.
- 필요한 문구만 기본 화면에 노출하고 범위·처리·오류 고지는 짧게 유지한다. 표의 모든 도움말을 한꺼번에 노출하지 않는다.
- 홈의 예시 사진은 제거하고, 참고 사진 추가 창에서4개 준비 가이드를 제공한다. 모바일의 화면 체험 버튼은 제거한다.
- F1 참고 사진은 입력 단서이며 검색 모집단은 연결한 갤러리 전체다.

### 3.1 세 입력과 세 결과 채널의 카피 적용 규칙

| 입력 | 이미지 원천 기반 후보 | 설명·조건 원천 기반 후보 | 종합 결과 |

|---|---|

| 중복 안내(필요시) | 같은 후보가 여러 기준에 표시될 수 있어요. 각 기준에서 더 살펴볼 수 있어요. |

**중요:** UI에 `TOP 3`, `3위`, `확률 n%` 표시는 필수 아님. 각 채널 최대 3개를 선노출할 뿐이며, **더보기를 누르면 해당 채널의 나머지 후보를 연속 탐색**할 수 있다. 같은 기록이 종합·이미지·맥락에 반복 등장해도 정상이다. `맥락`은 내부 용어로 두고 사용자용은 `설명·조건`으로 표시한다. 3개씩 배치·세로/탭은 실제 사용성 검증 후 결정한다.

결과가 0~2건이면 억지로 3개를 채우지 않는다. 사진 없는 기록은 종합/맥락 검색에 있을 수 있고 이미지 채널에는 없다. 입력/경로 오류와 실제 0건은 서로 다른 문구로 표시한다. F2 사진 전송과 외부 VLM 처리에는 필요한 고지·동의 및 제공자 정책 확인이 선행된다.

인증 제공자·보관/삭제 기간·백업 SLA는 미확정이므로 실제 화면에 임의 값을 쓰지 않는다. 운영 정책 링크가 준비되기 전에는 완료된 정책처럼 표현하지 않는다. 원본과 벡터의 성공이 모두 확인돼야 ‘등록했어요’를 표시한다.

## 6. F4 — 내 사진에서 습득물 검색으로

| 위치·상태 | 문안 |
|---|---|
| 진입 CTA | 이 사진으로 분실물 찾기 |
| 선택 제목 | 검색에 사용할 사진을 선택해 주세요. |
| 영역 선택 설명 | 사진 전체를 사용하거나 찾을 물건의 영역을 직접 선택할 수 있어요. |
| 선택 확인 | 선택한 사진 확인 |
| 전송 전 제목 | 이 사진으로 분실물을 찾을까요? |
| 전송 안내 제목 | 선택한 사진만 일시 전달해요. |
| 전송 안내 본문 | 분실물 검색을 위해 선택한 사진이나 영역만 서버에 일시 전달해요. 소중한 것들에는 자동 등록되지 않아요. |
| 상세 도움말 | 검색용 사진을 경찰 API에 자동 제출하지 않아요. |
| 확인 버튼 | 이 사진으로 계속 |
| 취소 | 취소하고 사진으로 |
| 전송 후 입력 안내 | 이 사진으로 바로 검색하거나 설명을 더할 수 있어요. |
| 원본 상실 | 선택한 원본을 열 수 없어요. 갤러리를 다시 연결한 뒤 사진을 선택해 주세요. |
| 전송 실패 | 사진을 전달하지 못했어요. 다시 시도하거나 다른 사진을 선택해 주세요. |

F1의 검색 범위에 ‘선택한 사진만’을 쓰지 않는다. 위 표현은 **F4 전송 범위를 알리는 경우에만** 사용한다.

### 7.1 기능 검증 후 노출할 보조 카피

| 항목 | 문안·조건 |
|---|---|
| 검색용 사본 축소 | 검색용 사본의 크기를 조정해요. 원본 파일은 바뀌지 않아요. — 실제 변환 시에만 |
| 축소 실패 | 검색용 사진을 준비하지 못했어요. 다른 사진을 선택하거나 다시 시도해 주세요. |
| 폴더 내 경로 복사 | 상대경로를 얻을 때 “폴더 내 경로 복사”, 파일명만 얻을 때 “파일명 복사”. 전체 절대경로 확보를 약속하지 않음 |
| 갤러리 준비 중 검색 | 현재 준비된 사진에서 검색했어요. — 실제 부분 검색을 허용하는 경우만 |
| 이미지 0건 | 사진 특징에 맞는 후보를 찾지 못했어요. |
| 맥락 0건 | 설명·조건에 맞는 후보를 찾지 못했어요. |

F3에는 등록 원본 전체를 보관해야 하므로 검색용 축소본으로 원본을 대체하지 않는다. 폴더·원본 경로 기능과 기관 주소/좌표 확보는 구현 검증이 필요하다. 기관명·공식 주소·지역을 대조해 같은 보관기관임이 확인된 좌표만 지도에 사용하며 검색 첫 결과를 임의 채택하지 않는다.

### 7.2 복사·진행·실패 문구의 노출 조건

“폴더 내 경로 복사”는 실제 상대경로를 확보할 수 있는 경우에만 버튼으로 표시한다. 파일명만 얻는 환경은 “파일명 복사”로 대체하고, 지원하지 않으면 숨긴다. 임시 URL·가짜 경로를 원본 경로로 복사하지 않는다.

F1의 “갤러리 전체에서 검색한 결과”는 연결 범위의 준비가 완료됐을 때 사용한다. 일부 준비 중/실패 시 실제 검색한 범위를 별도로 표시한다. F3의 “원본은 저장됐지만…”은 해당 등록의 모든 원본 저장 성공이 확인된 경우에만 사용한다. 일부 원본 실패는 “일부 사진 원본을 저장하지 못했어요. 등록은 아직 완료되지 않았어요.”로 구분한다. 삭제·등록 취소는 실제 정리 결과를 확인한 뒤 완료로 안내한다.

## 8. Figma 반영 시 구분할 내용

1. 위 문안은 **사용자에게 보일 카피 원고**다. ‘실제 연동 미검증’, ‘PROPOSED’, 정책 OPEN, 샘플 데이터 출처는 디자인 주석에서 관리한다.
2. 결과·지도·계정 등록·진행 상태를 예시로 보여 주는 현재 프레임에는 **샘플 화면 표시를 유지**한다. 실제 처리처럼 속이지 않는다.
3. ‘미구현’, ‘샘플로 등록 화면 보기’, ‘다음 샘플 단계’, ‘원본 열기 · 미구현’, ‘샘플 준비 완료 보기’는 실제 제품 버튼 카피에서 제거한다. 프로토타입 상태 탐색은 화면 밖 주석/검수 보드에서 제공한다.
4. ‘모든 이미지’는 F1의 검색 모집단을 설명한다. 참고 사진은 검색 입력이고, F4의 선택 사진은 전송 범위다. 세 개념을 섞지 않는다.
5. 화면 크기에 맞춰 문장을 다듬되 검색 범위·저장 범위·전송 범위·사진 없음·유사 후보·샘플 표시는 없애지 않는다.
