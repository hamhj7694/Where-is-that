## 1. 우선순위와 이번 구현의 경계

기준은 사용자 최신 지시 → 제품 정책 `00_상세기획안_그거어디_개정.md` → 화면 계약 `05_페이지구성_와이어프레임_UIUX_통합설계.md` → 승인 카피 `06_UI_최신_카피.md` 순으로 해석한다. 원본 문서는 `C:/Users/mbc/Documents/git/비전 AI 활용하여 웹서비스 만들기/vision_search_planning`에 있다. 최신 사용자가 홈 스타일로 나머지 모든 페이지의 프론트엔드 제작을 승인했으므로, 과거의 Figma 전용·홈 입력만 허용하던 범위보다 이번 지시를 우선한다.

### 최신 홈 규칙 — 다른 페이지에도 상속

- 별도 `홈` 메뉴는 만들지 않는다. 로고는 `/`로 돌아간다.
- 기능명은 `갤러리에서 사진 찾기`, `분실물 찾기`다.
- 두 기능 선택은 헤더 바로 아래에 두고 눌린 선택 상태를 유지한다. DML-019에 따라 `/`, `/gallery`, `/lost-found`에만 표시하며 결과·상세에서는 숨긴다.
- `소중한 것들`, `설정`, 별도 로그인/계정 행동은 유지한다. 모바일 헤더에 `화면 체험` 버튼을 복원하지 않는다.
- 홈의 예시 카드·예시 검색어 칩은 제거한다. 참고 사진의 준비 예시 4개는 사진 추가 모달 안에만 둔다.
- 기존 홈의 색·타입·입력창·버튼·간격을 상속한다. 새로운 페이지마다 별도 테마를 만들지 않는다.
- 제목은 과업, 설명은 꼭 필요한 범위·행동만 말한다. 같은 범위 안내를 한 화면에서 반복하지 않는다. 저장·전송·불확실성·샘플 표시는 짧게 유지한다.
- 긴 입력 예시·내부 모델명·처리 로그를 본문 설명으로 늘리지 않는다. 실제로 제공하지 않는 동작을 버튼처럼 표시하지 않는다.

F1 모달 소개는 `글이나 참고 사진으로 연결한 갤러리에서 찾아요.`처럼 짧게 유지한다. F2는 `분실 전 사진도 좋아요. 사진 없이도 검색할 수 있어요.`가 기준이다. 현재 실제 처리는 `이 브라우저에서만 미리 봐요. 서버로 전송하지 않아요.`로 정직하게 안내한다.

## 4. F1 필수 화면·상태

- **미연결:** 갤러리 연결과 참고 사진 추가를 분리한다. 사용자가 실제 연결하기 전 자동 권한 요청 없음.
- **파일 선택/폴더 선택:** 지원 가능한 방법만 노출. 폴더 미지원이면 직접 여러 이미지 선택. 확장자·읽기 가능 여부는 별도 취급한다.
- **실제 연결:** `연결한 갤러리 전체` + 실제 연결명·수. 부분 준비/실패가 있으면 전체 검색 완료라고 말하지 않는다.
- **색인 진행/중단/실패/재시도/재방문:** 최종 제품에 필수인 상태 UI를 샘플로 제작할 수 있다. 지금 실제 임베딩·색인을 수행했다고 표시하거나 임의 n/N·예상시간을 실제 처리처럼 사용하지 않는다.
- **결과:** 사진과 업무 스크린샷을 모두 담을 수 있는 그리드. 실제 File 데이터일 때 선택 순서/파일명 기반 목록과 AI 유사도순을 혼동시키지 않는다. 샘플 자료를 사용자가 고른 파일 사이에 끼워 넣지 않는다.
- **없음/접근 실패:** 현재 질의에 맞는 결과 없음, 원본 접근 실패, 갤러리 연결 없음은 별도 사유·복구 CTA.
- **사진 상세:** 실제 파일 확대, 파일명·파일 크기. 알려진 날짜만 표시. DML-025에 따라 복귀 문구는 `← 돌아가기`, 위치 복사 문구는 `파일 위치 복사`다. 폴더 연결에서 제공된 실제 상대경로만 표시·복사하며 개별 사진 선택으로 경로가 없으면 비활성+폴더 연결 안내를 제공한다. 파일명·fakepath·blob URL을 원본 경로로 복사하지 않는다.
- **재연결/해제:** 실제 메모리 연결을 정리한다. 원본 삭제·서버 삭제와 구별. 현재 없는 지속 인덱스를 삭제했다고 말하지 않는다.
- **F4 진입:** `이 사진으로 분실물 찾기`. 누르기 전 F2 draft·계정 자료를 변경하지 않는다.

근거: FR-GAL-01~09, FR-AUTH-01/05, NFR-LOCAL-01/02, 06 §2/7.2.

## 5. F2 두 채널·전체보기 계약

| 입력 | 사진 특징 경로 | 설명·조건 경로 |
|---|---|---|
| 자연어만 | 공공 실사진의 VLM 맥락과 문장의 관련도 비교가 필수 | 자연어를 전체 공개 기록의 실제 설명·조건과 비교 |
| 사진만 | 입력 사진과 공공 실사진의 관련·시각 특징 비교 | 입력 사진 VLM 해석으로 종류·색상·형태·특징을 자동 구성해 검색 |
| 혼합 | 명시 문장+입력 사진 특징을 함께 반영 | 문장+추정 사진 특징으로 설명·조건 검색, 충돌은 수정 가능 |

이번에는 위 처리를 실제로 실행하지 않는다. 입력 타입은 실제 입력으로 결정하고, 샘플 데이터의 두 채널을 별도로 보여준다. `사진만이라 설명 검색 미지원`이나 `글만이라 이미지 경로 숨김`으로 필수 UX를 축소하지 않는다.

- 정상 요약: **사진 특징 최대5 + 사진 특징 후보 전체 보기 / 설명·조건 최대5 + 설명·조건 후보 전체 보기**.
- 이미지 카드: 유효한 실제 물품 사진이 있는 샘플 기록만. 깨진 이미지·기본이미지는 실제 물품 사진이 아니다.
- 맥락 카드: 사진 있는 기록과 없는 기록을 함께 포함. 사진이 없으면 `등록된 사진 없음`; 없는 설명·기관·브랜드를 생성하지 않음.
- 요약 중복 제거는 두 채널의 화면 중복만 줄이는 제안이다. 맥락 모집단에서 사진 있는 기록 전체를 제거하지 않는다.
- 각 경로 5개 미만을 정상 지원한다. 관련 없는 카드를 채워 숫자를 맞추지 않는다.
- 전체보기는 해당 경로만 확장한다. 실제 동작하는 클라이언트 `더 불러오기`/페이지 이동으로 샘플 데이터도 요약보다 많은 항목을 확인할 수 있게 한다. 현재 전체 항목보다 많은 총건수를 만들지 않는다.
- 필터는 적용/해제/초기화가 실제 샘플 목록에 반영되게 한다. 습득지역·습득장소·보관기관 주소는 같은 필드가 아니다.
- `사진에서 추정한 특징`과 `관련 단서`는 샘플/실제 원문/사용자 입력의 출처를 구분한다. 현재 실제 VLM을 돌려 사용자 사진의 특징을 추출했다고 말하지 않는다.
- 질의·필터 변경 시 두 경로를 같은 새 요청으로 갱신하고 이전 요청 결과를 섞지 않는다. 실패 경로만 재시도할 때 정상 결과는 유지한다.
- 점수·일치 확률·실시간성·소유권·회수 보장 없음. 실제 API 조회 시각이 없으면 그럴듯한 갱신 시간을 표시하지 않는다.

근거: FR-LOS-01~09, 16~28, 05 §6~7, 06 §3.

### F2 필수 상태표

| 상태 | 사진 특징 | 설명·조건 | 사용자 복구 |
|---|---|---|---|
| loading | 독립 준비 표시 | 독립 준비 표시 | 실제 취소를 제공할 때만 취소 |
| S1 | 1~5건 | 1~5건 | 각 전체보기·상세·검색 수정 |
| S2 | 성공·0건 | 정상 | 조건 수정·설명 후보 |
| S3 | 정상 | 성공·0건 | 조건 수정·사진 후보 |
| S4 | 성공·0건 | 성공·0건 | 조건 수정·공식 검색 |
| S5 | 오류 | 정상 | 사진 경로만 재시도 |
| S6 | 정상 | 오류 | 설명 경로만 재시도 |
| S7 | 입력 해석 오류/확인 필요 | 입력 해석 오류/확인 필요 | 재시도·필요한 동의·선택적 입력 보완. 가능한 정상 결과 유지 |
| S8 | 기록 변경/지연 | 기록 변경/지연 | 공식 정보·새로고침·기관 확인 |
| source error | 원천 전체 실패 | 원천 전체 실패 | 다시 시도·공식 검색 |

오류+0건은 전체0건이 아니다. 다른 경로의 실제 후보가 있을 때만 `다른 후보는 계속 확인할 수 있어요`를 추가한다. 동의 미완료는 처리되지 않은 상태이며 0건이 아니다. 샘플 실패 상태 선택기는 제품의 기본 과업과 구분된 체험/QA 영역에 두고, 모든 카드를 실패 상태로 임의 재해석하지 않는다.

## 6. F2 상세·위치

필수 순서: 사진 또는 사진 없음 → 물품명·분류·색상·습득일·관리번호·습득 장소·접수기관(존재하는 값만) → 설명·공식 출처 → 유사 후보 안내 → **하단 보관기관 및 위치**.

| 위치 상태 | 지도 | 필수 내용·행동 |
|---|---|---|
| verified | 작은 보조 지도1개·마커1개 | 검증된 현 보관기관·주소·연락처·공식 정보. 실제 목적지가 있을 때만 길찾기 |
| address_only | 없음 | 확인된 주소, 좌표 미확인 안내·공식 정보 |
| ambiguous | 없음 | 정확한 기관 위치 미확인·공식 정보/문의 |
| missing/invalid | 없음 | 확인된 위치 없음·존재하는 공식 정보만 |
| provider_error | 없음 | 지도를 불러오지 못함. 이미 검증된 주소·전화는 유지 |

현재는 실제 좌표·기관 검증이 없으므로 실제 물건의 verified로 표시하지 않는다. verified 레이아웃이 필요하면 **샘플 지도 · 실제 위치가 아니에요**라는 컨셉 시안으로 분리하고 실제 목적지 링크는 만들지 않는다. 지도·길찾기보다 후보 사실과 기관 확인이 먼저다. 전체 결과 지도·다중 마커·GPS 권한은 제공하지 않는다.

공식 상세 URL이 없으면 없는 링크를 생성하지 않는다. 일반 경찰청 공식 검색으로 보낼 때 버튼을 `공식 검색`으로 쓰고 `이 후보 공식 상세`처럼 보이게 하지 않는다. 가상 기관명·전화번호를 실제 기관처럼 노출하지 않는다.

카피: `같은 물건인지는 아직 확인되지 않았어요.` / `방문 전 기관에 보관 여부를 확인해 주세요.`. 출처별 기록 ID·기관·확인 시점은 샘플 여부를 유지한다. 이미지 로딩 실패·기록 삭제·직접 진입한 없는 ID에도 상세 복구를 제공한다.

근거: FR-LOS-10~15, 05 §8, 06 §4.

## 7. F3 인증·목록·등록·관리

### 인증 경계

- F3는 최종 제품에서 로그인 필수다. `/valuables`, `/new`, 상세·수정·삭제 직접 진입에도 게이트와 원래 목적지 복귀가 있어야 한다.
- 이번 실제 인증은 연결하지 않는다. 체험 세션과 실제 로그인 계정을 구별하고, 자격증명/비밀번호를 수집하거나 보호된 계정 서버가 생겼다고 말하지 않는다.
- 체험 세션이 목록·등록·관리 화면을 체험할 수 있게 하되 짧은 체험 표시를 유지한다. 세션 만료·로그아웃·취소 후 F1/F2는 계속 이용 가능하다.
- `returnTo`는 같은 서비스의 허용 경로만 사용한다. 외부 URL로 로그인 후 이동시키지 않는다.

### 필수 화면·상태

| 화면 | 주행동·내용 | 필수 상태 |
|---|---|---|
| 로그인 게이트 | 계정 보관 이유, 로그인/체험 진입·돌아가기 | guest, 실패, 취소, 만료·복귀 |
| 물품 목록 | 사진·이름·보관중/분실/찾음, 물건 등록 | 빈 목록, 샘플 목록, 실제 메모리 체험 항목 |
| 새 등록/검토 | 이름·분류·색상/특징·추가 설명, 원본1~N·추가/교체/빼기, 저장 범위 | 필수값 오류·읽기 실패·취소·검토 |
| 처리 상태 | 원본 저장 → 검색용 정보 준비 → 완료의 UI | 원본 실패·일부 원본 실패·벡터 실패·재시도·정리 실패 |
| 상세 | 원본 재열람·특징·상태, 수정·삭제·F2 연결 | 원본 없음·없는 항목·세션 만료·접근 오류 |
| 수정 | 기존 값·사진 변경, 저장·취소 | dirty, 오류, 취소 시 이전 자료 유지 |
| 삭제 확인 | 원본·검색용 정보·썸네일·등록정보 삭제 범위 | 취소, 처리, 실패, 성공·목록 복귀 |

최종 저장 고지: **등록한 사진 원본 전체와 사진별 AI 검색용 정보가 내 계정 서버에 저장돼요. 소중한 것들에서 확인하고 삭제할 수 있어요.** 상세 안내에 사진별 임베딩 벡터를 설명한다.

이번 메모리 체험 저장은 원본 File을 실제 유지·다시 보기할 수 있게 하고 새로고침 후 소실을 알린다. 썸네일/축소본만 남기고 원본이 저장됐다고 하지 않는다. 벡터를 만들지 않으므로 서버 원본+벡터 등록 완료라고 표시하지 않는다. 체험 항목 저장과 최종 제품의 완료·부분 실패 시안은 상태를 구분한다. 샘플 처리 UI도 실제 네트워크 진행률·가짜 모델 로그처럼 보이지 않게 한다.

`원본은 저장됐지만…`은 그 등록의 모든 원본 성공이 확인된 경우에만 사용한다. 부분 원본 실패를 같은 메시지로 덮지 않는다. 삭제·등록 취소는 실제 메모리 자료·미리보기 참조를 정리한 뒤 완료로 안내한다. 운영 백업의 삭제기간·정책 URL을 임의 생성하지 않는다.

근거: FR-AUTH-03~07, FR-VAL-01~10, 06 §5/7.2.

## 8. F4 명시적 사진 전달

1. F1 사진 상세에서 사용자가 `이 사진으로 분실물 찾기`를 선택한다.
2. 확인 화면에 **그 사진**을 미리 보여준다. 현재 전체 사진만 지원하면 영역 선택기를 넣지 않는다. 사진 앱에서 잘라 준비하는 가이드는 제공 가능하다.
3. 최종 제품 정책인 선택 사진/영역만 일시 전달·F3 자동 등록 없음과, 이번 체험에서 서버 전송이 없는 사실을 혼동 없이 짧게 구분한다.
4. `이 사진으로 계속`을 눌렀을 때만 F2의 참고 File로 연결하고 추가 설명 입력 또는 바로 검색을 허용한다. F1의 다른 파일은 복사하지 않는다.
5. `취소하고 사진으로`는 원래 사진 상세로 돌아가며 F2 draft를 바꾸지 않는다.
6. 원본 참조 소실·선택 취소·전달 실패는 복구·재선택을 제공한다. 직접 URL 진입만으로 F2 입력을 변경하지 않는다.
7. 기존 F2 참고 사진/입력이 있으면 조용히 덮어쓰지 않는다. 교체가 필요할 때만 짧은 확인을 제공하고 텍스트 유지·교체 범위를 명확히 한다.

F3의 `이 물건으로 분실물 찾기`도 사용자가 실제 선택한 등록 사진을 명시적으로 F2에 전달한다. F3 목록 진입·물품 상태 변경만으로 자동 검색·전송하지 않는다.

근거: FR-GAL-08, FR-VAL-04, F4 사용자 합의, 06 §6.

## 9. 설정·계정·삭제

- `/settings`에는 `갤러리 사진 검색 · 이 브라우저`와 `소중한 것들 · 내 계정`을 분리한다.
- 현재 실제 기능은 연결 갤러리·메모리 자료 관리다. `연결 해제`가 원본 삭제·서비스 계정 삭제가 아님을 명시한다.
- 로컬 인덱스가 없는 지금 저장 공간·최근 색인 시각·삭제 완료를 허위 표시하지 않는다. 최종 제품의 로컬 인덱스 삭제 상태는 별도 샘플로 표현 가능하다.
- `/account`의 체험 로그아웃은 체험 세션·체험 계정 자료만 정리한다. F1 연결 갤러리까지 삭제·분리된다고 말하지 않는다.
- 계정 전환만으로 같은 브라우저의 F1 자료가 별도 계정 데이터가 되는 것으로 처리하지 않는다.
- 실제 계정 탈퇴·비밀번호 변경·OAuth 관리·백업 복원·계정 동기화·검색 속도 혜택은 이번 기능으로 추가하지 않는다.
- 개인정보 안내는 현재 브라우저 처리와 최종 서비스의 F1 로컬/F2 일시/F3 계정 원본+벡터/F4 선택 전달 경계를 설명한다.

## 11. 상태 선택·직접 URL·데이터 수명

- 기본 사용자 흐름과 오류 체험/QA 제어를 분리한다. 상태 URL을 쓴다면 `?state=image-error`, `?location=missing` 등은 체험 제어이며 실제 서버 상태로 가장하지 않는다.
- 세 입력은 실제 draft를 사용한다. 사용자 사진을 바꿔도 샘플 후보가 동일하다면 AI 분석 결과처럼 설명하지 않는다.
- 새로고침으로 메모리 File·체험 등록 항목·세션이 없어지는 경로는 정상 복구 화면으로 연결한다.
- Object URL은 이미지 교체·빼기·모달 취소·자료 삭제·unmount 시 해제한다. 같은 File의 다른 화면이 사용 중이면 해당 소비자의 수명과 별도로 관리한다.
- File 경로·OCR·질의·사진을 분석 로그·URL·localStorage에 자동 장기 보관하지 않는다.
- F1/F2 입력, F3 체험 목록, F4 pending을 별도 자료로 유지한다. 모드 전환 중 비동기 읽기 완료가 다른 모드에 사진을 삽입하지 않게 한다.
- 검색 조건·선택 결과·직전 채널·가능한 스크롤을 복귀 시 복원한다. 없는 기록이나 다른 질의 결과를 이전 화면으로 가장하지 않는다.

## 12. 반응형·접근성·짧은 카피 수용 기준

- 모든 필수 라우트를 Desktop 1440, Mobile 390/360에서 확인하고 Tablet768/1280 중간 폭도 검수한다.
- 이미지 후보는 데스크톱3~5열·모바일2열, 맥락 후보는 세로 정보 목록. 5번째 결과·두 번째 섹션·전체보기 링크가 숨지 않아야 한다.
- 상세는 데스크톱 사진/사실2열 가능, 모바일 사진→사실→설명→기관/위치 순서.
- 모달의 제목·닫기·확인/취소는 스크롤 중에도 접근 가능. 본문 스크롤과 배경 스크롤이 혼동되지 않게 한다.
- textarea에는 실제 존재하는 설명 ID만 `aria-describedby`로 연결한다. IME·포커스·오류/부분성공 상태 알림을 유지한다.
- 터치 목표44px, 본문/작은 안내문 대비4.5:1을 실제 측정한다. 색만으로 선택·오류·채널을 구분하지 않는다.
- 긴 한국어 제목·긴 파일명·정보누락·사진없는 카드5개·등록사진여러개·키보드가 열린 모바일을 검수한다.
- Esc→같은 모달 재열기, 닫은 뒤 시작버튼/입력으로 초점 복귀, Tab 순서·시트·직접 URL 접근을 확인한다.
- 소비자 화면에서 `미구현`, 모델 설치명, 서버 계약, 가짜 분석로그, `다음 샘플 단계` 같은 제작 지침을 주행동으로 사용하지 않는다. 체험·샘플 여부는 짧고 사실적으로 표시한다.

## 14. 권장 최종 사용자 클릭 흐름

1. **F1 실제 로컬 파일:** 로고/갤러리 모드 → 갤러리 연결 → 폴더 또는 사진 여러장 선택 → 글/참고 사진 입력 → 로컬 사진 미리보기/결과 체험 → 실제 사진 상세 → 원본 미리보기·경로/파일명 복사 → 결과 복귀.
2. **F2 글만:** 분실물 모드 → 글 입력 → 샘플 두채널 결과 → 사진 특징 전체보기 → 후보 상세 → 하단 기관/위치 대체 → 원래 채널 → 요약 → 설명·조건 전체보기 → 사진 없는 후보 상세.
3. **F2 사진만:** 참고 사진 추가 → 분실 전 사진 가이드 → 실제 File선택·미리보기 → 이 사진 사용 → 글 없이 검색 → 샘플 두채널 결과. 혼합은 같은 흐름에 자연어만 더한다.
4. **부분 실패:** 두채널 결과 체험 → 한 경로 실패 상태 → 정상 경로의 후보 상세까지 계속 이동 → 실패 경로만 재시도. 두 경로0건에서는 조건 수정/공식 검색.
5. **F3 계정 체험:** 소중한 것들 → 로그인 목적/체험 범위 → 로그인 화면의 체험 세션 → 빈 목록/샘플 목록 → 물건 등록 → 실제 원본1~N·이름·특징 → 검토 → 메모리 체험 저장 → 상세 → 수정·취소/저장 → 삭제확인·취소/삭제 → 목록.
6. **F4:** 실제 F1 사진 상세 → 이 사진으로 분실물 찾기 → 선택 사진 확인·일시전달 범위 → 확인 → F2에 그 사진만 첨부 → 글 추가 선택 → 샘플 두채널 결과. 취소 시 F2 draft 무변경.
7. **설정·계정:** 설정 → 갤러리 관리/연결 해제 → 원본 보존 확인 → 재연결. 계정 → 등록 물건 관리/체험 로그아웃 → F1/F2 계속 이용.
8. **직접 URL·모바일 복구:** 새로고침한 로컬 상세/체험 물품 상세 → 참조 없음 안내 → 재연결/목록 복귀. 모바일 메뉴·상단 모드·모달닫기·브라우저뒤로가기로 같은 과업을 완료한다.

## 17. 최신 결과 편집·도우미 구현 계약 — DML-023/024

- **검색 수정:** 결과 요약을 같은 페이지의 공통 컴포저로 전환한다. 글/사진/크롭을 바꾼 뒤 ‘다시 검색’하면 현재 기록 ID·생성 시각·연결 갤러리 스냅샷은 유지하고 질의/참고 사진을 교체한다. 도우미 조건·대화·초안은 초기화한다. 취소는 확정된 입력·기록·도우미를 유지한다. 채널 더보기에서는 해당 채널을 유지하고 페이지/개발 상태 파라미터만 초기화한다.
- **참고 사진:** 결과 요약에서96×96px, 클릭/키보드 확대 후 ‘사진 변경·수정’으로 기존 참고 사진 추가/영역 선택 기능에 연결한다. 편집 사본은 전체 검색 수정 확정 전까지 기록에 저장하지 않는다. 사진 창 취소 후 현재 컴포저 입력으로 초점을 복귀한다.
- **텍스트:** 요약은 한 줄 말줄임, 넘침 또는 줄바꿈이 있으면 펼치기/접기를 제공한다. 펼친 질의와 도우미의 조건은 줄바꿈을 보존한다. 모바일도96px 사진 옆에 문구와 버튼을 정렬한다.
- **도우미 조건:** 적용한 조건과 새 조건을 개별 수정/삭제한다. 저장·삭제만으로 검색하지 않으며 ‘이 조건으로 다시 검색’에서 기본 질의+현재 조건 전체를 합친 새 자식 기록을 만든다. 적용한 조건도 계속 편집 가능하게 유지한다. 같은 문구의 중복 누적을 방지하고 모든 적용 조건 삭제 시 기본 질의로 재검색할 수 있다. 이전 스키마 기록은 부모 관계와 질의/대화가 확인될 때만 조건을 복원한다.
- **높이:** body 최대PC336px/모바일288px(기존280/240px 대비20%), 전체 최대768px와 viewport 상한을 함께 적용한다. 대화 영역만 스크롤하고 작성 입력·재검색 버튼은 고정된 패널 영역에 둔다. 낮은 화면에서는 body가 줄어든다. 키보드로 body를 스크롤할 수 있다.
- 최신 검수:8개 파일143개 테스트, lint/typecheck/build 통과. 격리360/390/1440px·1100×480px에서 큰 사진·줄바꿈·같은 기록 덮어쓰기·조건 편집·내부 스크롤을 확인했다. 실제 모델 검색/AI 답변/실기기 검수는 미완료다. 상세 증거와 사용자 확정 사항은 마스터 작업 로그를 따른다.
