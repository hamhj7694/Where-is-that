# 프론트엔드 전체 화면

- **최우선 디자인 기준:** `../vision_search_planning/10_디자인_마스터_작업로그.md`의 사용자 확정 사항은 09 마스터 기획서 및 다른 디자인 문서보다 우선한다. 작업 0·1의 메뉴·카피·갤러리 표시·체험 숨김을 후속 개선에서 되돌리지 않는다. 새로운 사용자 변경은 기존 로그를 삭제하지 않고 추가 기록한다.
- 현재 승인 범위는 2026-11-17 작업 0·1. 전체 화면 재설계는 일시정지 상태다. `/history`는 현재 브라우저 메모리 기록이며 실제 검색 성공/영속 저장을 주장하지 않는다.
- 후속 확정: 미연결 F1은 홈·`/gallery`에서 인페이지 갤러리 연결이 먼저이며 검색 컴포저를 렌더하지 않는다. 연결 팝업을 되살리지 않는다. 연결 썸네일은 PC112px·모바일96px, 클릭·키보드 확대와 닫기 포커스 복귀를 유지한다.
- DML-005: 선택 폴더의 모든 하위 폴더 이미지를 수집하며 미리보기4장으로 모집단을 제한하지 않는다. 제목 옆 관리·해제, 사진4장 뒤 ‘이미지 더보기’ 실제 연결목록을 유지한다. 해제는 확인 후 연결·갤러리 기록만 정리하며 원본·F2 기록·F3를 보존한다.
- 최신 DML-006/007: 미연결 제목은 ‘찾고 싶은 사진이 있는 갤러리나 폴더를 연결해 주세요.’, 두 갤러리 목록에서 파일명 필터 삭제. 모바일 미리보기56px·간격4px가 위96px 이력보다 우선한다. PC112px·확대 유지. 기록 중복 묶기는 미확정 제안이며 임의 적용하지 않는다.
- DML-008: PC는 미리보기 최대6장, 전체7장 이상에서만 더보기 표시. PC6장 이하에서는 더보기를 숨긴다. 모바일은56px·최대4장+남은 이미지 더보기 구성을 유지한다.
- DML-009/010: F1 참고사진 창의 큰 미리보기·같은 dialog 안 사각형 편집·하단 단계별 확정을 유지한다. 원본 복귀 정보는 컴포넌트 재진입에도 유지하되 File 세션 메모리 밖에 저장하지 않는다. 영역 적용만으로 draft를 바꾸지 않고 최종 ‘이 사진 사용’에서 확정한다. F1 설명은 ‘연결한 갤러리에서 사진이나 스크린샷을 찾을 수 있어요.’이다.
- 최신 DML-011이 PC 개수 기준을 대체한다: 미리보기 최대7장, 전체7장 이하 더보기 숨김·8장 이상 표시. 모바일56px·최대4장 및 나머지 더보기는 유지한다.
- DML-012/013: 찾은 기록은 행별 휴지통·복구 불가 확인·취소 후 ID 한 건만 삭제한다. 원본/다른 기록/검색 초안은 보존하고 삭제 후 초점을 복귀한다. F1 첨부 사진 미리보기64px도 클릭·키보드로 기존 참고 사진 추가 창을 다시 열며 검색을 제출하지 않는다.
- 최신 DML-014/015/016: 관리 화면의 ‘연결 갤러리 유지하며 돌아가기’는 연결을 유지하고 브라우저 직전 경로로 복귀한다. PC는 전체7장 이하 전부 표시·더보기 없음, 8장 이상 사진6장+더보기다. DML-011의 8장 이상 사진7장 기준을 대체하며 모바일56px·최대4장은 유지한다. 검색 결과 제목은 ‘찾은 이미지’이며 해당 결과 헤더의 관리 버튼을 제거한다. 전체 연결목록 ‘연결한 이미지’와 구별한다.
- 최신 DML-017: 위 관리 화면 복귀 버튼의 표시 문구는 ‘← 돌아가기’다. DML-014의 긴 카피를 대체하며 연결 유지·직전 경로 복귀 동작은 유지한다.
- 최신 DML-018이 미리보기 액션 기준을 대체한다: PC6장 이하는 전부+‘이미지 추가’, 7장 이상은 사진6장+‘이미지 더보기’만 표시한다. 추가는 기존 File/순서/초안/기록을 유지하고 사진·하위 폴더 전체 이미지를 뒤에 연결한다. 모바일4장/56px를 유지하고5~6장에서는 더보기와 다음 줄44px 추가 버튼을 함께 제공한다. 취소·무효 선택은 연결을 바꾸지 않는다.
- DML-019: 헤더 아래 ‘갤러리에서 사진 찾기 / 분실물 찾기’ 검색 방식 선택 바는 정확히 `/`, `/gallery`, `/lost-found`에서만 표시한다. 결과·이미지 전체목록·상세와 다른 페이지에는 렌더하지 않는다. 기존 뒤로가기·검색 수정·헤더 메뉴는 유지한다.
- DML-020: ‘연결한 이미지’ 전체목록의 gallery-toolbar 왼쪽 끝에 ‘이미지 추가’를 표시하고 기존 정렬은 오른쪽에 유지한다. 연결 장수와 관계없이 기존 사진·폴더 추가 창을 사용하며, 과거 검색 결과에는 이 버튼을 넣지 않는다.
- DML-021: 새 갤러리 연결은 선택 안의 중복, 이미지/폴더 추가는 현재 연결 및 선택 안의 중복을 파일 내용(SHA-256)으로 제외한다. 동명·다른 내용은 유지한다. 파일 확인은 로컬·순차이며 취소/화면 종료/새 요청으로 취소된 처리는 commit하지 않는다. 검사 중 안내·취소, 전체 중복 안내, 읽기 실패 시 기존 연결/입력/기록 보존을 유지한다. 기존 누적 중복의 선제 정리는 별도다.
- DML-022: F1 ‘찾은 이미지’에 종합/이미지/맥락 각 최대3장과 독립 더보기·페이지·상태를 제공한다. 현재는 연결 File의 배치 미리보기이며 실제 AI 순위/답변을 만들지 않는다. 기록별 검색 도우미의 조건·대화·초안·열림을 보존하고 명시적 ‘이 조건으로 다시 검색’에서만 새 기록을 만든다. 결과에는 관리/이미지추가/모드바를 넣지 않으며 view=all 목록은 기존 동작을 유지한다.
- 최신 DML-023: 결과 참고 사진은96px·클릭 확대·사진 변경/영역 편집을 제공한다. 질의는 한 줄 미리보기/펼치기와 줄바꿈을 유지한다. ‘검색 수정’은 현재 결과 안의 컴포저로 전환하며 확정 시 같은 ID의 검색/참고 사진을 덮어쓰고 도우미를 초기화한다. 취소는 기존 상태를 보존한다. 도우미 조건은 이미 적용한 조건까지 수정/삭제 가능하며, ‘이 조건으로 다시 검색’의 새 기록 생성은 유지한다. 재적용 후 조건을 비우던 DML-022 부분만 대체한다.
- DML-024: 도우미 대화 영역의 최대 높이는 PC336px·모바일288px로 기존 대비20% 늘린다. 패널 전체는 최대768px 및 화면 높이 안으로 제한하며 .gallery-assistant__body만 스크롤한다. 입력·적용 버튼의 패널 내 위치를 유지하고 낮은 화면에서는 대화 영역이 먼저 줄어든다.
- DML-025: 개별 이미지의 정상/누락 화면 복귀 문구는 ‘← 돌아가기’. 기존 back의 결과 채널/기록/페이지를 보존한다. ‘파일 위치 복사’는 File.webkitRelativePath의 폴더 기준 경로만 복사한다. 위치를 상세에 표시하고 상대 위치임을 안내한다. 사진만 선택해 경로가 없으면 버튼 비활성+폴더 연결 안내를 제공한다. 파일명/blob/fakepath/추측한 절대 경로를 위치로 복사하지 않는다.
- DML-026: 찾은 기록의 두 영역 모두 검색 내용은 기본 최대2줄, 실제 표시가3줄 이상일 때만 펼치기/접기를 제공한다. 수동 줄바꿈과 폭에 따른 자동 줄바꿈을 함께 판정하고 원문은 보존한다.44px 독립 토글은 결과 Link 밖에 두며 결과 이동·삭제/확인·초점 동작을 유지한다.
- DML-027: F2 참고 사진도 공통 큰 미리보기·동일 dialog 내 사각형 영역 선택·전체 사진 복원·첨부 사진 클릭 재편집을 제공한다. 영역 적용은 임시 상태, 최종 ‘이 사진 사용’에서만 확정하며 취소는 기존 첨부 유지. 원본은 세션 메모리에 보존한다. 여러 사진/세그먼트/배경 제거/생성 이미지는 제안·미구현이며 이번 확정 범위로 확대 해석하지 않는다.

2026-11-16~17 사용자 최신 지시로 홈·검색 입력 및 같은 스타일의 전체 페이지 프론트엔드 개발을 승인받았다. 루트 AGENTS.md의 과거 Figma 전용 범위/구현 보류보다 이 지시가 우선한다. 기존 Figma를 변경하지 않는다. 상세 인벤토리는 docs/SCREEN-INVENTORY.md를 따른다.

- 제품 정책: 상위 planning/00, 화면 구조:05, 승인 카피:06. 05의 오래된 카피 예시보다06이 우선한다.

- F2: 글만/사진만/혼합 모두 이미지·설명조건 두 경로. 서버·AI 연결 전인 현재는 입력 요약만 표시하고 실제 결과를 만들지 않는다.
- 실제 동작: 라우트/모드별 독립 입력, 파일 미리보기/제거, 폴더·사진 선택, 검증, 모달. 갤러리 선택과 모든 사진 처리는 메모리 안에서만 수행하며 새로고침 후 유지되지 않는다.
- 실제 AI/API/인증/서버 저장은 이번 프론트엔드 범위 밖이다. F2 후보·지도 구성·저장 진행 상태는 명확한 샘플로만 구현한다. F1 실제 파일 목록을 AI 유사도 검색 결과로 표현하지 않는다. F3 임시 항목을 서버 등록 완료로 표시하지 않는다.
