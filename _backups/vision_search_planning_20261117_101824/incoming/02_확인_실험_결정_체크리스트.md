## 0. 상태·증거 체계

- 상태: `미시작 → 준비 → 실행 → 결과검토 → 승인/보류/기각/차단`.
- 증거: **E0** 아이디어·예측 / **E1** 공식 명세·정책 / **E2** 실제 API·코드 재현 / **E3** 고정 데이터셋·정량 비교 / **E4** 실사용자·보안/운영 반복 검증.

- 승인 표기 템플릿: `DEC-ID | 현재 상태 | 근거(E#) | 선택 | 제외한 대안 | 리스크 | 승인자 | 승인일 | 영향 FR/API/디자인`.

## 4. 최신 브랜드 결정을 위한 최소 실사용자 테스트 (`EXP-23`)

**합성 500/5,000명 가상 투표를 실제 데이터로 간주하지 않는다.** 모집한 실제 사용자(예: 12~20명 탐색 테스트 초안, 통계적 대표성 보장 안 됨)에게 다음을 묻는다.

1. **이름만** 보여주고: “어떤 서비스일 것 같나요?” — 자유서술, 사진 검색·유실물 검색·GPS/택배/경찰 공식 서비스 예상 여부 코딩.
2. `그거어디?` 옆 `내 사진 · 내 물건 찾기` 보여주고 예상 기능 재확인.
3. 비교 시안 `내 사진 내 물건 그거찾기`, `내 사진도, 내 물건도. 그거찾기!`로 교차 비교(순서 편향 방지).
4. F2 상세 하단 지도 안내를 본 뒤 “지도가 뜻하는 위치는 무엇인가?” — 습득 장소와 보관 장소를 구별하는가?
5. 이름을 읽고·입력하고·다시 기억하게 해 발음/띄어쓰기/질문부호 혼동 확인.
6. [KIPRIS](https://www.kipris.or.kr/khome/main.do)에서 동일·유사 표기·발음·관련 서비스업 검토, 관련 도메인·SNS/스토어 중복 검토. **법적 등록 적합성은 전문가 확인 가능**.

## 5. API/지도 결정표 (주소 정확성이 우선)

| 상태 | 의미 | F2 상세 행동 | 금지 |
|---|---|---|---|
| `verified` | 공식 기관과 주소·좌표 매칭 근거 확인 | 기관 카드 + 소형 지도 + 외부 길찾기 | 물건 실시간 GPS로 표현 |
| `address_only` | 확인된 주소·연락처, 좌표 미검증 | 주소·전화·공식 링크, 지도 숨김 | 대략 위치 핀 |
| `ambiguous` | 기관명 중복/주소 충돌 | 후보 기관을 단정하지 않고 공식 문의 | 첫 검색결과를 단정 |
| `missing` | 기관/주소 누락 | 공식 상세/고객 문의 및 새로고침 | 임의 기관 생성 |
| `invalid` | 잘못된 좌표·지역 불일치 | 지도 숨기고 오류 정정대기 | 좌표 보정 흉내 |
| `provider_error` | 지도 서비스/쿼터 장애 | 상세 메타 유지, 다른 링크 제시 | 검색 전체 실패 처리 |

**공공 API 자료와 상표 관련 현행성:** 공식 홈페이지 자료를 확인했더라도 **우리 계정의 API 키 실호출/상표 출원 조회/도메인 소유 조회를 수행했다는 뜻이 아님**. 문서 명세(E1)와 구현 증거(E2)를 엄격히 구분.
