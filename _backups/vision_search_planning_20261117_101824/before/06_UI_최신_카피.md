# 그거어디? — 최신 UI 카피

v1.0 · 2026-11-16 · 검토 반영 원고 · 현재 제작 Figma 화면에 반영(미제작 상태 원고 제외)

**F2 입력·결과 계약 [AGREED · 2026-11-16]:** 자연어만 / 사진만 / 자연어+사진의 세 입력 모두 이미지 기반 검색과 맥락 기반(설명·조건) 검색을 실행한다. 자연어만 입력해도 **VLM이 공공 습득물의 유효한 실제 사진에서 읽은 맥락·물체·특징을 질의와 비교하여 관련도를 산정**한다. 사진만 입력해도 **VLM이 입력 사진/선택 영역의 종류·색상·형태·눈에 보이는 특징을 해석하여 설명·조건 검색을 자동 수행**한다. 혼합 입력은 자연어와 사진의 특징을 함께 반영한다. 정상 결과 화면에는 **이미지 후보 5건 + 해당 경로 전체 보기 / 설명·조건 후보 5건 + 해당 경로 전체 보기**를 독립적으로 제공한다. 각 5건은 관련 후보가 충분할 때의 목표이며, 실제 후보가 0~4건이면 있는 만큼만 표시한다. 임의 후보로 채우거나 입력 종류만을 이유로 한 경로를 생략하지 않는다.

**필수 범위와 검증 경계:** F2의 VLM 기반 이미지 이해와 세 입력×두 검색 경로는 필수 요구다. 구체 모델·제공자·색인·랭킹·품질·비용·지연·외부 전송 정책은 검증 전이다. 공공 사진 사전 분석/색인/캐시와 후보 재비교를 조합할 수 있으며 매 질의마다 모든 사진을 전수 재분석하도록 고정하지 않는다. 임베딩 단독 실험은 비교 기준선일 뿐 필수 VLM 맥락 처리를 대체하지 않는다. VLM 실패·시간 초과·입력 해석 불확실·동의 미완료는 오류/확인 필요로 표시하고 정상적인 0건이나 입력 미지원으로 위장하지 않는다. 사진 없는 공공 기록은 이미지 경로에서 제외하되 **맥락 경로의 검색 모집단에 유지**한다. VLM 추출 정보는 공식 원문과 별도로 관리하며 동일 물건·소유권·회수를 확정하지 않는다.

카피의 목적·범위는 00, 화면 계약은 05, 시각 실행은 01을 따른다. 아래 문구는 화면에 적용할 원고이며 실제 기능·API·VLM 검증 완료를 주장하지 않는다. 제작자 지침은 사용자에게 노출하지 않는다.

## 문구를 판단하는 기준

서비스는 사용자가 기억하는 말이나 참고 사진으로 원하는 이미지를 찾고, 공개 습득물에서 비슷한 후보를 살펴보도록 돕는다. 큰 제목은 사용자 목적을 말하고, 작은 안내는 검색 범위·입력 방법·저장 사실·실패 후 행동을 설명한다. 제작 상태·API 구현 여부·인증 공급자 결정 여부를 실제 사용자용 문장에 섞지 않는다. 해당 내용은 디자인 주석으로 관리한다. 샘플 화면과 실제 검색 결과의 구분은 계속 표시한다.

**F1의 검색 대상은 연결한 갤러리 전체다. 참고 사진 한 장은 검색에 쓰는 입력이며, 검색 범위를 그 사진 한 장으로 제한하지 않는다.** 갤러리는 사용자가 연결하고 접근을 허용한 사진 모음이다. 기기의 모든 폴더를 허락 없이 읽는다는 뜻이 아니다. 읽을 수 없는 형식·권한 문제는 별도 상태로 알린다.

‘갤러리 전체 검색’과 ‘원본·인덱스 보관 위치’는 다른 정보이므로 한 문장으로 묶지 않는다.

### 3.1 세 입력과 두 결과의 카피 적용 규칙

| 입력 | 이미지 기반 검색 — 사진 특징 후보 | 맥락 기반 검색 — 설명·조건 후보 |
|---|---|---|
| 자연어만 | 공공 실사진의 VLM 맥락·물체·특징과 자연어 설명의 관련도를 비교한다. 사용자 사진 첨부를 요구하지 않는다. | 자연어를 공개 기록의 물품명·설명·분류·색상·조건과 비교한다. |
| 사진만 | 입력 사진/선택 영역과 공공 실사진의 시각 특징·VLM 맥락을 비교한다. | 입력 사진을 VLM으로 해석해 검색용 설명·조건을 자동 구성하고 사진 유무 무관한 공개 기록을 검색한다. 자연어 추가 입력을 요구하지 않는다. |
| 자연어+사진 | 입력 문장과 사진 특징을 함께 반영해 공공 실사진 후보의 관련도를 판단한다. | 자연어와 VLM이 읽은 입력 사진의 설명·조건을 함께 반영한다. 사용자 입력과 AI 추정의 충돌은 표시·수정 가능하게 한다. |

| 위치 | 사용자 문구 |
|---|---|
| 두 결과 안내 | 어떤 방식으로 입력해도 사진 특징과 설명·조건으로 각각 찾아요. |
| 공통 작은 안내 | AI 검색은 잘못 찾거나 놓칠 수 있어요. |
| 사진 입력의 자동 추출 | 사진에서 추정한 특징 |
| 특징 보완 행동 | 특징 수정 / 특징 빼기 |
| 이미지 경로 결과 | 사진 특징이 비슷한 후보 / 사진 특징 후보 전체 보기 |
| 맥락 경로 결과 | 설명·조건이 비슷한 후보 / 설명·조건 후보 전체 보기 |

사진/설명 추가는 검색 품질 개선을 위한 선택이다. “설명을 적어야 설명·조건 검색 가능” 또는 “사진을 첨부해야 사진 특징 검색 가능”을 정상 입력 안내로 사용하지 않는다. 해석 실패나 필요한 동의 미완료는 실제 예외로 안내한다. 각 5건은 목표/최대치이며 실제 부족·0건·오류를 구분한다.

다른 경로의 후보가 실제 존재할 때만 “다른 후보는 계속 확인할 수 있어요.”를 덧붙인다. 한 경로 오류+다른 경로 0건은 전체 검색 완료·전체 0건이 아니다. 추정 특징과 공식 기록의 근거를 구분한다.

F1의 검색 범위에 ‘선택한 사진만’을 쓰지 않는다. 위 표현은 **F4 전송 범위를 알리는 경우에만** 사용한다.

|---|---|
| 검색용 사본 축소 | 검색용 사본의 크기를 조정해요. 원본 파일은 바뀌지 않아요. — 실제 변환 시에만 |
| 축소 실패 | 검색용 사진을 준비하지 못했어요. 다른 사진을 선택하거나 다시 시도해 주세요. |
| 폴더 내 경로 복사 | 상대경로를 얻을 때 “폴더 내 경로 복사”, 파일명만 얻을 때 “파일명 복사”. 전체 절대경로 확보를 약속하지 않음 |
| 갤러리 준비 중 검색 | 현재 준비된 사진에서 검색했어요. — 실제 부분 검색을 허용하는 경우만 |
| 이미지 0건 | 사진 특징에 맞는 후보를 찾지 못했어요. |
| 맥락 0건 | 설명·조건에 맞는 후보를 찾지 못했어요. |

F3에는 등록 원본 전체를 보관해야 하므로 검색용 축소본으로 원본을 대체하지 않는다. 폴더·원본 경로 기능과 기관 주소/좌표 확보는 구현 검증이 필요하다. 기관명·공식 주소·지역을 대조해 같은 보관기관임이 확인된 좌표만 지도에 사용하며 검색 첫 결과를 임의 채택하지 않는다.

### 7.2 복사·진행·실패 문구의 노출 조건

“폴더 내 경로 복사”는 실제 상대경로를 확보할 수 있는 경우에만 버튼으로 표시한다. 파일명만 얻는 환경은 “파일명 복사”로 대체하고, 지원하지 않으면 숨긴다. 임시 URL·가짜 경로를 원본 경로로 복사하지 않는다.

F1의 “갤러리 전체에서 검색한 결과”는 연결 범위의 준비가 완료됐을 때 사용한다. 일부 준비 중/실패 시 실제 검색한 범위를 별도로 표시한다. F3의 “원본은 저장됐지만…”은 해당 등록의 모든 원본 저장 성공이 확인된 경우에만 사용한다. 일부 원본 실패는 “일부 사진 원본을 저장하지 못했어요. 등록은 아직 완료되지 않았어요.”로 구분한다. 삭제·등록 취소는 실제 정리 결과를 확인한 뒤 완료로 안내한다.

## 8. Figma 반영 시 구분할 내용

1. 위 문안은 **사용자에게 보일 카피 원고**다. ‘실제 연동 미검증’, ‘PROPOSED’, 정책 OPEN, 샘플 데이터 출처는 디자인 주석에서 관리한다.
2. 결과·지도·계정 등록·진행 상태를 예시로 보여 주는 현재 프레임에는 **샘플 화면 표시를 유지**한다. 실제 처리처럼 속이지 않는다.
3. ‘미구현’, ‘샘플로 등록 화면 보기’, ‘다음 샘플 단계’, ‘원본 열기 · 미구현’, ‘샘플 준비 완료 보기’는 실제 제품 버튼 카피에서 제거한다. 프로토타입 상태 탐색은 화면 밖 주석/검수 보드에서 제공한다.
4. ‘모든 이미지’는 F1의 검색 모집단을 설명한다. 참고 사진은 검색 입력이고, F4의 선택 사진은 전송 범위다. 세 개념을 섞지 않는다.
5. 화면 크기에 맞춰 문장을 다듬되 검색 범위·저장 범위·전송 범위·사진 없음·유사 후보·샘플 표시는 없애지 않는다.
