# 그거어디? — 전체 아키텍처 · 기능별 파이프라인 · 실패 분기

> v1.1 / 2026-11-16 / **도표는 설계안(PROPOSED) + 승인된 데이터 정책(AGREED)**. 실제 구축·API 실연동·성능 검증 결과 아님.  
> 범위: F1 내 사진 찾기 / F2 잃어버린 물건 찾기(상세 **하단** 보조 지도) / F3 소중한 것들 / F4 선택 연계 / F5 설정·검색 상태.  
> PPT 짝 파일: `05_파이프라인_시각도표_그거어디.pptx` — 단계/용어와 요구사항 ID가 대응됨.

## 0. 읽는 법 및 필수 정책

- `[AGREED]`: 제품 요구로 합의됨. `[PROPOSED]`: 기술·구현 초안. `[EXPERIMENT]`: 성능/규정 미검증.
- 첫 홈은 **그거어디?** + 헤더 설명 **내 사진 · 내 물건 찾기**. 비로그인 채팅형 검색 입력과 **F1/F2 선택**. F3 진입 때만 로그인.
- F1 **로컬 원본/벡터**, F2 **공공 검색 인덱스**, F3 **계정 서버의 사용자가 등록한 원본 전체+사진별 벡터**. 세 저장 공간을 하나로 합치지 않음.
- F2 결과는 **유사 후보**. 상세 **하단**에만 보관기관 정보/소형 지도; 지도는 **현 보관기관의 확인된 위치**이지 실제 물건의 GPS가 아님.
- 검증된 지도 위치가 없으면 **지도 없음** + 공식 출처·기관 문의. 잘못된 핀을 보여 주는 것보다 미표시가 낫다.

    G --> F3[F3: 명시 등록 원본 + 사진별 벡터 서버 보관]
    A -->|예| F3
    F1 -->|사용자 명시 선택만| X[F4: 선택한 사진/크롭 일시 전달]
    X --> F2
    F3 -->|사용자가 등록 물품 선택| F2

**저장 경계:** 위 다이어그램의 로컬·공공·계정 데이터 저장은 **논리적/권한적 분리**를 뜻한다. 같은 개발 PC·프로세스에서 실행해도 데이터 영역·접근·삭제는 독립적으로 관리한다.

## 3. F1 최초 인덱싱 및 비로그인 재방문

```mermaid
flowchart TD
    START[F1 접근·로그인 불필요] --> PERM{폴더/파일을 사용자가 허용?}
    PERM -->|아니오| FBACK[권한 안내·다중 파일 선택 대안]
    PERM -->|예| VALID[원본·EXIF·수정시각·MIME/크기 확인]
    VALID --> EMB[브라우저 로컬 모델 추론: 임베딩]
    EMB --> OPT{추가 처리 이득 검증?}
    OPT -->|예| OCR[선택: OCR · 수동/모델 크롭]
    OPT -->|아니오| INDEX[(로컬 인덱스 저장)]
    OCR --> INDEX
    INDEX --> READY[F1 검색 준비]
    READY --> RETURN{브라우저 재방문}
    RETURN -->|권한·인덱스 유효| DELTA[변경분만 재처리 후 검색]
    RETURN -->|권한 만료/데이터 삭제| RECONNECT[재연결·재인덱싱 안내]
```

**핵심 계약:** 인증 없음, 원본 기기 잔존, IndexedDB 등 로컬 벡터 재사용 시나리오. `showDirectoryPicker()`/브라우저 AI의 실제 가능성은 `EXP-09/13/14` 전제. 서버 업로드는 F1 기본 경로가 아니다.

## 4. F1 사용자 검색: 텍스트 · 이미지 · 혼합

```mermaid
flowchart LR
    Q[텍스트 / 이미지 / 둘 다] --> T[브라우저 로컬 쿼리 처리]
    T --> V[같은 모델 계열의 텍스트·이미지 벡터]
    V --> R[(로컬 사진·크롭 벡터 검색)]
    R --> K[Top-K 후보 + 선택적 OCR 메타 결합]
    K --> RESULT[사진 카드 · 원본 열기 · 관련 사진]
    RESULT --> NEXT{사진 안 물건으로 F2 검색?}
    NEXT -->|아니오| END[F1 종료]
    NEXT -->|예| CONFIRM[F4 대상 사진/영역·전송 안내]
```

**UX:** 단순히 큰 LLM 답변이 아닌 이미지 카드 리스트. 오탐 후보는 ‘관련 사진’으로 표시하고, F1 원본 파일을 열 수 없는 경우 재연결/인덱스 정리 제공. OCR은 실험 후 선택.

```mermaid
flowchart TD
    API1[경찰관서 습득물 API] --> RAW[원문·출처 식별자·변경 시각]
    API2[포털기관 습득물 API] --> RAW
    RAW --> LICENSE{수집/캐시/이미지 색인 권한 확인?}
    LICENSE -->|미확인| BLOCK[공공 이미지 색인 보류·대체 텍스트 검토]
    LICENSE -->|허용| NORMAL[품목·사진·습득일·기관·중복 정규화]
    NORMAL --> IMAGE[이미지 유효성 검사·임베딩 생성]
    IMAGE --> PUBIDX[(공유 F2 공공 검색 인덱스)]
    USER[비로그인 사용자 F2: 텍스트·이미지·혼합] --> QUERY[질의 모델 처리 / 수동 크롭 옵션]
    QUERY --> PUBIDX
    PUBIDX --> RANK[코사인/메타 소프트 필터·Top-K]

    CAND --> DETAIL[개별 후보 상세: 물품 정보 우선]

```

**명칭:** F2 공급원은 공공데이터포털 경찰청 API이며, 경찰 내부 기록을 직접 조회하는 서비스라고 표현하지 않는다. 결과의 점수를 '동일 실물 확률'로 번역하지 않는다.

## 6. F2 후보 상세: 주소/지도 **검증 분기**

```mermaid
flowchart TD
    D[F2 상세: 사진·설명·습득 정보] --> META[출처 원문: 습득장소 vs 보관장소 분리]
    META --> RESOLVE[보관기관 코드·기관명 정규화]
    RESOLVE --> OFFICIAL[기관 공식 주소·전화·갱신일 대조]
    OFFICIAL --> UNIQUE{기관/주소를 유일하게 확인?}
    UNIQUE -->|아니오| NO[지도 숨김 / 공식 상세·전화 안내]
    UNIQUE -->|예| GEO[주소→좌표 변환 / 좌표 검증]
    GEO --> VALID{위치 verified?}
    VALID -->|아니오 / API 오류| NO
    VALID -->|예| MINI[상세 **하단 소형 지도: 단일 기관 마커**]
    MINI --> EXTERN[외부 지도 열기·길찾기]
    MINI --> CALL[방문 전 기관 연락 / 공식 상세 확인]
    NO --> CALL
```

**데이터 계약:** `found_place_raw`(습득 지점) ≠ `intake_place_raw`(접수처) ≠ `custody_place_raw`(보관기관). 지도는 **현 보관기관의 확인된 주소**만. 반환·이동·기관명 중복·지도 API 장애 시 임의 핀 금지. `EXP-22` 후 `DEC-LOC-01` 승인 필요.

### 지도 상태별 UI 처리

| 상태 | 작은 지도 | 보조 정보·복구 |
|---|---|---|
| `verified` | **있음** | 기관명·주소·전화·확인일, 외부 지도·길찾기·공식 링크 |
| `address_only` | 없음 | 주소·전화·공식 링크; 좌표 검증 안 됨 |
| `ambiguous` | 없음 | 동명 기관/여러 주소 → 공식 확인 문의 |
| `missing` | 없음 | 기관/주소 없음 → 공식 상세·조회 갱신 |
| `invalid` | 없음 | 지리정보 충돌 → 관리대상 검증 |
| `provider_error` | 없음 | 지도 API 실패·쿼터 → 정보 유지, 외부/문의 대안 |

**화면 범위:** `F2 리스트 카드 → F2 상세 본문 → 하단 보조 소형 지도`만. 검색 결과 전체 지도, 인근 지도 검색, GPS 실시간 위치추적 없음.

## 7. F3 소중한 것들: 원본 **전부**와 사진별 벡터

```mermaid
flowchart TD
    ENTRY[F3 메뉴 선택] --> LOGIN{서버 인증 완료?}
    LOGIN -->|아니오| GATE[로그인 이유·원본 저장 설명 → 인증]
    LOGIN -->|예| SELECT[물품 사진 여러 장·설명 입력]
    GATE --> SELECT
    SELECT --> DISC[원본 전체 + AI 특징/벡터 계정 저장 고지]
    DISC --> SAVE[계정 보호 원본 파일 저장]
    SAVE --> EMB[photo_id별 임베딩 + 모델 버전 생성]
    EMB --> CHECK{원본·벡터 연결 모두 확인?}
    CHECK -->|실패| ROLLBACK[등록 미완료 표시·재시도/롤백]
    CHECK -->|성공| LIST[원본 다시 보기·상세/수정·삭제]
    LIST --> LOST{분실 상태에서 F2로 검색?}
    LOST -->|예| F2[F2 후보 검색; 공식 확인]
    LOST -->|아니오| END[등록·보관 유지]
```

**데이터 소유자:** 계정 서버에 사용자가 **직접 선택 등록한 원본 사진 전체**와 **각 사진의 검색 벡터**를 함께 저장. F1 전체 갤러리는 절대 자동 저장 안 함. 계정 간 접근 차단, 백업·탈퇴·사진별 삭제 전파, 원본+벡터 실패 시 성공 허위표시 금지 (`EXP-16/21`).

## 8. F4 선택적 F1→F2 사진 전달 (프라이버시 경계)

```mermaid
flowchart LR
    F1[F1에서 검색한 로컬 원본] --> SELECT[사용자 사진·대상 물체/크롭 선택]
    SELECT --> NOTICE[이 사진만 F2 일시 검색에 사용 고지]
    NOTICE --> CONSENT{사용자가 명시적으로 실행?}
    CONSENT -->|아니오| ABORT[원본 기기에 유지]
    CONSENT -->|예| TRANSFER[필요한 이미지/특징만 F2에 전달]
    TRANSFER --> COMPAT{F2 모델과 벡터 호환?}
    COMPAT -->|아니오| REEMB[F2용 일시 재임베딩]
    COMPAT -->|예| SEARCH[F2 검색]
    REEMB --> SEARCH
    SEARCH --> CLEAN[임시 질의 파일·작업 데이터 삭제]
```

**경계:** F4의 일시 전송이 F3 계정 보관 승인이 아니다. 서버에 개인 이미지를 장기 보관하지 않음. AI가 특정 물건을 자동으로 확정하지 않으며 수동 선택·취소 경로 필수 (`EXP-17`).
