> 중요: F1=비로그인·로컬 사진, F2=비로그인·공개 습득물 유사 후보, F3=로그인·등록한 **원본 사진 전체+사진별 벡터**를 계정 서버 저장, F4=명시적 선택 후 F1→F2 일시 전달.
> **화면·와이어프레임 단일 기준:** `05_페이지구성_와이어프레임_UIUX_통합설계.md`. 이 Figma 문서는 **시각 스타일·컴포넌트·제작 순서**를 관리하고 페이지별 상세 UI 명세를 중복하지 않는다. F2 검색 결과는 **이미지 TOP 5 + 이미지 전체 보기 / 맥락 TOP 5 + 맥락 전체 보기**의 두 섹션 목표 UX로 변경했다(검색 품질은 미검증).

**F2 입력·결과 계약 [AGREED · 2026-11-16]:** 자연어만 / 사진만 / 자연어+사진의 세 입력 모두 이미지 기반 검색과 맥락 기반(설명·조건) 검색을 실행한다. 자연어만 입력해도 **VLM이 공공 습득물의 유효한 실제 사진에서 읽은 맥락·물체·특징을 질의와 비교하여 관련도를 산정**한다. 사진만 입력해도 **VLM이 입력 사진/선택 영역의 종류·색상·형태·눈에 보이는 특징을 해석하여 설명·조건 검색을 자동 수행**한다. 혼합 입력은 자연어와 사진의 특징을 함께 반영한다. 정상 결과 화면에는 **이미지 후보 5건 + 해당 경로 전체 보기 / 설명·조건 후보 5건 + 해당 경로 전체 보기**를 독립적으로 제공한다. 각 5건은 관련 후보가 충분할 때의 목표이며, 실제 후보가 0~4건이면 있는 만큼만 표시한다. 임의 후보로 채우거나 입력 종류만을 이유로 한 경로를 생략하지 않는다.

**필수 범위와 검증 경계:** F2의 VLM 기반 이미지 이해와 세 입력×두 검색 경로는 필수 요구다. 구체 모델·제공자·색인·랭킹·품질·비용·지연·외부 전송 정책은 검증 전이다. 공공 사진 사전 분석/색인/캐시와 후보 재비교를 조합할 수 있으며 매 질의마다 모든 사진을 전수 재분석하도록 고정하지 않는다. 임베딩 단독 실험은 비교 기준선일 뿐 필수 VLM 맥락 처리를 대체하지 않는다. VLM 실패·시간 초과·입력 해석 불확실·동의 미완료는 오류/확인 필요로 표시하고 정상적인 0건이나 입력 미지원으로 위장하지 않는다. 사진 없는 공공 기록은 이미지 경로에서 제외하되 **맥락 경로의 검색 모집단에 유지**한다. VLM 추출 정보는 공식 원문과 별도로 관리하며 동일 물건·소유권·회수를 확정하지 않는다.

## 0. 이 문서로 만들 것 / 만들지 않을 것

**만들 것**: 브랜드 워드마크·심벌 시안, 디자인 토큰, 재사용 컴포넌트, desktop/mobile 주요 화면, 각 기능의 정상·로딩·오류·권한·빈 결과, 핵심 사용자 흐름 프로토타입, 최종 개발 핸드오프.  
**만들지 않을 것**: API 검증 전 실제 경찰 데이터를 조회하는 것처럼 꾸민 화면; F1 사진이 서버에 자동 업로드되는 화면; F2 전체 지도를 메인 UX로 만든 화면; 로그인·백업을 F1 검색 혜택으로 내세운 화면; F2를 소유권 확정·반환 보장으로 표현한 결과.

## 1. 브랜드 ID와 이야기

### 이름 및 카피 계층

- 워드마크(우선 채택 작업안): **그거어디?**
- 헤더 옆 디스크립터(권장): **내 사진 · 내 물건 찾기**
- 사용자 요청 장문 카피 비교안: **내 사진 내 물건 그거찾기**. 헤더에서 읽기 복잡한지 실제 A/B 확인. 문장으로 쓰면 `내 사진도, 내 물건도. 그거찾기!`를 캠페인형 후보로 사용.
- 브랜드 비전(기획 문서): **소중한 순간과 물건을, 기억나는 단서만으로 다시 찾을 수 있도록.** 그러나 UI 헤드라인에서 ‘단서’를 반복적으로 강조할 필요는 없음.
- 브랜드 경험의 서사: **그거 어디 있지? → 기억나는 말이나 사진으로 찾아보기 → F1: 아, 여기 있네! / F2: 혹시 이 물건인가요?**
- 과제 공식 주제: `AI 기반 개인 사진 탐색 및 유실물 검색 웹서비스`. 브랜드명이 공식 주제를 대체하지 않음.
- 상표·도메인·기능 오인 검증 전 외부 출시명 법적 확정 아님(`EXP-23`).

### 톤앤매너: C. Calm & Meaningful

1. **인상**: 믿을 수 있고 차분하지만 건조하지 않은 개인 검색 도구. 필요한 곳에서만 따뜻한 발견의 기쁨.
2. **레퍼런스 방향**: 차분한 에디토리얼 공간, 명확한 검색 입력, 정보가 우선인 결과 카드, 따뜻한 뮤트 컬러. 과도한 AI 네온·글래스모피즘·캐릭터 남발·경찰/탐정 상징 금지.
3. **감성의 위치**: 홈 헤드라인·온보딩·F1 실제 발견 성공. **오류·보안·유실물 후보·연락 안내는 사실 중심 카피**.
4. **사진 중심**: 제품 설명이 길어도 사진·물품 썸네일 자체가 가장 눈에 띄게. 지도는 F2 상세 하단의 보조.
5. **이미지 정책**: 실제 데이터 미확보 단계의 썸네일·지도·기관은 `샘플`임을 표시. 가짜 습득물 기관명이나 관리번호를 실제처럼 묘사하지 않음.

### 3.1 신규 F2 이중 검색 화면 제작 기준

- **화면의 정확한 와이어프레임·페이지 ID·두 섹션 중복/전체 보기·상태 정의는 `05_페이지구성_와이어프레임_UIUX_통합설계.md` 6~7장 참조.** 이 가이드에 상세 화면 도형을 중복 작성하지 않는다.
- 섹션 A `사진 특징이 비슷한 습득물`은 **유효한 실사진 보유 후보만** 사진 그리드로 표시, 최대 5건과 이미지 전체 보기 제공.
- 섹션 B `설명·조건이 비슷한 습득물`은 **사진 유무 무관한 전체 기록**을 텍스트·메타 중심 세로 카드로 표시, 최대 5건과 맥락 전체 보기 제공. 이미지 TOP 5에 노출된 후보의 요약 중복만 피하는 방식은 제안안.
- 사진 없는 기록은 `등록된 사진 없음` 표기. 생성한 이미지를 실제 공공 습득물 사진처럼 사용하지 말 것. 이미지 섹션이 실패해도 맥락 섹션을 표시하고 반대도 동일.
- 점수/일치 확률 비교, 실제 API 이미지 존재율, 필수 VLM의 구체 모델·정렬·페이지네이션은 **실험 전 미확정**. `DEMO` 화면에 실제 경찰 기록처럼 보이는 정보 금지.
- D0 필수 시안: `F2-05` desktop/mobile 정상, `no-photo` 맥락 카드, `image-empty/context-success`, `image-error/context-success`; 각 경로 전체 보기의 진입·후보 목록·상세·요약 복귀도 D0 필수다. D1에서는 검증된 정렬·페이지네이션·전체 예외 상태를 확장한다.

### 3.2 F2 세 입력×두 결과 필수 제작 계약

| 입력 | 이미지 기반 검색 — 사진 특징 후보 | 맥락 기반 검색 — 설명·조건 후보 |
|---|---|---|
| 자연어만 | 공공 실사진의 VLM 맥락·물체·특징과 자연어 설명의 관련도를 비교한다. 사용자 사진 첨부를 요구하지 않는다. | 자연어를 공개 기록의 물품명·설명·분류·색상·조건과 비교한다. |
| 사진만 | 입력 사진/선택 영역과 공공 실사진의 시각 특징·VLM 맥락을 비교한다. | 입력 사진을 VLM으로 해석해 검색용 설명·조건을 자동 구성하고 사진 유무 무관한 공개 기록을 검색한다. 자연어 추가 입력을 요구하지 않는다. |
| 자연어+사진 | 입력 문장과 사진 특징을 함께 반영해 공공 실사진 후보의 관련도를 판단한다. | 자연어와 VLM이 읽은 입력 사진의 설명·조건을 함께 반영한다. 사용자 입력과 AI 추정의 충돌은 표시·수정 가능하게 한다. |

- 자연어만 / 사진만 / 혼합 각각의 정상 프레임에서 두 섹션과 각 전체 보기를 제공한다. 한 입력 유형에 한 경로를 숨기거나 설명을 필수로 추가하게 하는 시안은 만들지 않는다.
- 각 5건은 후보가 충분할 때의 목표다. 실제 후보가 적으면 0~4건을 표시하고 정상 0건과 VLM 처리 실패를 다른 상태로 만든다.
- 입력 사진의 자동 특징은 “사진에서 추정한 특징”으로 표시하고 수정·빼기를 제공한다. 공공 VLM 설명은 공식 원문 사실과 구분한다.
- VLM 장애/시간 초과/동의 미완료는 예외 상태이며 입력 유형의 정상 미지원 상태가 아니다. 재시도와 선택적 입력 보완을 제공하고 정상 경로는 유지한다.
- 화면·핸드오프는 `FR-LOS-23~28`, `EXP-24`, 05 §6.4-A를 참조한다. VLM 품질과 실제 API 연동은 이 문서 작성으로 검증되지 않는다.

## 4. F2 상세 페이지: 지도의 정확한 위계

```text
[이전 결과로]                  [공식 출처 확인]
[물품 사진/확대]
[물품명]  [유사 후보/확정 아님]
습득일 · 물품분류 · 색상 · 관리번호(있는 경우)
습득 장소 (있을 때) / 접수처 (있을 때)
물품 상세 설명 및 특이사항
──────────────────────────────────────────
보관기관 및 위치    ← 상세 페이지의 **하단 보조 섹션**
기관명 / 확인된 주소 / 연락처 / 정보 확인일
[소형 단일 마커 지도: verified일 때만]
[지도에서 보기] [길찾기] [공식 상세 확인] [전화]
※ 실시간 위치가 아니며 방문 전 보관 여부를 문의하세요.
```

**디자인 상태 6개**

1. `verified`: 보관기관 주소+좌표 검증 → 소형 지도 + 전화/외부 길찾기.
2. `address_only`: 공식 주소는 있으나 지오코딩 미확정 → **지도 없음**; 주소와 공식 문의 표시.
3. `ambiguous`: 같은 이름 기관 여러 곳 → **지도 없음**; 첫 검색 결과 임의 선택 금지.
4. `missing`: API에 기관/주소 누락 → **지도 없음**; 공식 상세 링크.
5. `provider_error`: 지도 API 장애·쿼터 초과 → **지도 없음**; 기관명/전화/주소 유지.
6. `record_changed`: 물품 반환/기록 변경 의심 → 갱신/출처 확인 안내, 지도가 남더라도 물건 보관 확정 금지.

**범위 밖:** 지도 중심 홈, 주변 습득물 탐색, 결과 목록 핀 지도, 지도 기반 정렬, 서비스 내부 경로 탐색, GPS 위치 수집. 지도 SDK는 데이터 정확성 `EXP-22` 통과 시 도입, 안 되면 공식기관 안내만 남기는 것이 더 안전.

| 맥락 섹션 | `설명·조건이 비슷한 후보` / `설명·조건 후보 전체 보기` | 사진만 입력해도 VLM 자동 설명 검색 |
| 추출 특징 | `사진에서 추정한 특징` | 공식 원문과 구별·수정 가능 |
| 공통 안내 | `AI 검색은 잘못 찾거나 놓칠 수 있어요.` | 오류·누락 가능성 |
| 공공 사진 누락 | `공개 기록에 사진이 없으면 사진 특징으로 비교할 수 없어요. 설명·조건으로도 함께 찾아요.` | 사용자 사진 미첨부와 구별 |
| F3 저장 | `등록한 사진 원본 전체와 사진별 AI 검색용 정보가 내 계정 서버에 저장돼요. 소중한 것들에서 확인하고 삭제할 수 있어요.` | 원본/벡터·삭제 경로 |
| F4 전송 | `선택한 사진이나 영역만 분실물 검색을 위해 서버에 일시 전달해요. 소중한 것들에는 자동 등록되지 않아요.` | 선택 범위·일시 처리 |

사진만 입력했을 때 “설명을 입력해야 검색 가능”을 정상 카피로 쓰지 않는다. 해석 실패·검색 실패와 추가 설명의 선택적 보완은 06의 오류 문구로 구분한다.

## 8. 사용성 검증·승인 체크리스트

- [ ] 브랜드명만 보고 GPS·위치 추적/일반 인터넷 검색을 오인하는지 기록(`EXP-23`).
- [ ] 시각적 헤더가 `그거어디?`/기능 설명/로그인/네비를 구분하고 360px에서 깨지지 않음.
- [ ] 게스트가 ① F1 ② F2 검색을 회원가입 없이 시작할 수 있음.
- [ ] F1 최초 인덱싱 비용·로컬 저장·브라우저 권한/삭제 리스크를 정확히 표현함.
- [ ] **F2 결과는 이미지 TOP 5/전체 보기와 맥락 TOP 5/전체 보기를 독립 구획**으로 보여준다.
- [ ] **맥락 결과는 사진 없는 기록도 검색 가능**하고 이미지 섹션만 실패해도 유지된다.
- [ ] `등록된 사진 없음`은 가짜 실사로 대체하지 않는다. 이미지/맥락 검색 점수를 확률처럼 병합하지 않는다.
- [ ] F2 결과 카드와 상세를 분리; 상세 상단은 사진과 물품 정보, 지도는 **하단 보조**.
- [ ] 유사 후보와 동일 물품 확정의 차이를 누구나 이해하고, 공식 출처를 찾을 수 있음.
- [ ] 지도 데이터가 애매하거나 API가 실패할 때 **임의 핀 없음**. 기관 연락/공식 정보 경로 남음.
- [ ] F3 계정에는 **선택 등록한 모든 원본 사진+사진별 검색 벡터** 저장 사실, 삭제 경로가 적혀 있음.
- [ ] F1→F2는 사진 선택·명시적 전송 클릭 후 일시 처리, 자동 F3 등록 없음.
- [ ] 모바일 터치·스크린리더·키보드·색 대비·긴 텍스트·이미지 없음/중복 등 상태 검수.
- [ ] 컴포넌트와 페이지의 미검증 상태는 `DEMO` / `PROPOSED` / `AGREED` 중 하나로 표시.

- [ ] 자연어만 / 사진만 / 자연어+사진 각각에서 이미지·설명/조건 **두 경로를 모두 실행**한다.
- [ ] 자연어만으로 공공 사진의 VLM 맥락을 비교하고, 사진만으로 입력 사진의 VLM 설명·조건을 추출한다.
- [ ] 각 경로 0건 / 1~4건 / 5건 / 6건 이상에서 최대 5건 요약과 해당 경로 **전체 보기**를 확인한다.
- [ ] 전체 보기는 질의·필터·경로와 복귀 맥락을 유지한다. 요약 중복 제거가 전체 후보를 영구 제외하지 않는다.
- [ ] 사용자 사진 미첨부와 공공 기록 사진 누락을 구분하고, 사진 없는 공개 기록을 맥락 검색에 남긴다.
- [ ] VLM 실패·시간 초과·해석 불확실·동의 필요·0건을 구분한다. 정상 경로는 유지하고 실패 경로만 재시도한다.
- [ ] 공공 원문과 VLM 파생 특징의 출처를 구분하고, 모델/프롬프트 버전·처리 시각·이미지 버전·상태를 추적한다.
- [ ] F1 전체 갤러리 무단 전송·F3 자동 등록·경찰 API 개인 사진 제출이 없고, 필요한 외부 전송 고지·동의를 확인한다.

## 9. 개발 핸드오프 파일/링크 규칙

- Figma frame별: `frame_id`, `route`, `user_goal`, `FR-ID`, `state`, `layout`, `data_contract`, `edge_case`, `decision_status` 기록. **전체 페이지·와이어프레임·상태 진실 원천은 `05_페이지구성_와이어프레임_UIUX_통합설계.md`.**
- 컴포넌트별: variant 이름, props·디자인 토큰 매핑, 접근성 텍스트, 실제 실패 사례, 애니메이션·모바일 규칙.
- 지도는 `location_resolution_status`를 받아 `verified`에서만 지도 컴포넌트 노출. 주소/전화/출처 출처 및 확인일의 존재 여부에 따라 문구 변경.
- 최종 디자인 승인 전 `EXP-18/19/20/22/23`와 `DEC-LOC-01` 확인. 개발자가 Figma 디자인만 보고 서버 정책을 임의 추론하지 않도록 상세 기획안·API 목록과 함께 전달.
